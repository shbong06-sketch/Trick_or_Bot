# tob_perception 임시 설계 문서

- 작성일: 2026-10-10
- 설계 변경일: 2026-10-11
- 담당: 봉승현
- 상태: 세부 설계 용.
- 작업 원칙: 작업 전 계획을 검토하고, 파일 수정은 사용자 승인 후 진행한다.

## 1. 설계 목표와 범위

AMR 카메라의 압축 RGB 영상을 구독하고 PT 모델로 Pumpkin을 탐지한 뒤, bbox 기준 포착 조건을 만족한 대상만 `detected=true`로 `/tob/perception/pumpkin_detection`에 발행한다.

우선 구현 범위는 모델 로딩, 영상 디코딩, 추론, bbox 기반 포착 판정, 대상 선택, 탐지 메시지 및 선택적 디버그 영상 발행이다. 위치 계산 단계에서는 두 로봇의 AMCL 지도 위치를 관측에 연결하여 기준점 사이의 평면 거리를 계산하고 최종 observation을 발행한다. 위치 계산의 세부 설계와 후속 검증은 13절에서 다룬다. 이 문서는 구현 계획이며 해당 기능의 구현 완료를 의미하지 않는다.

## 2. 사용자 확정 사항

- 입력 토픽: `/robot1/oakd/rgb/image_raw/compressed`.
- 모델 경로는 ROS 파라미터로 지정한다.
- 기본 모델: `yolo11n_boo.pt`.
- 추론 장치: GPU.
- `--debug` 실행 옵션을 지정한 경우에만 탐지 결과를 그린 디버그 영상을 발행한다.
- 포착 여부는 depth나 AMCL 거리 대신 RGB bbox 크기로 판정한다.
- 위쪽 잘림으로 높이·면적이 작아지는 문제를 줄이기 위해 정규화 bbox 너비를 우선 기준으로 사용한다. 임계값은 실측 후 확정한다.
- 거리 계산은 두 로봇의 AMCL 지도 위치를 사용하는 방식으로 우선 진행한다.
- depth 및 2D LiDAR 기반 측정은 AMCL 거리의 실측 오차가 요구 정확도를 만족하지 못할 때 검토한다.

## 3. 탐지 인터페이스 기준

- `docs/interfaces.md`
- `ros2_ws/src/tob_interfaces/msg/TargetObservation.msg`

실제 메시지 필드 이름과 타입은 `TargetObservation.msg`를 따른다. 바운딩 박스는 원본 RGB 영상 기준으로 정규화한 0~1 값이다.

## 4. 탐지 처리 흐름

```text
/robot1/oakd/rgb/image_raw/compressed
  → boo_detector_node.py: 압축 영상 디코딩
  → detector.py: GPU 모델 추론
  → 대상 클래스 및 신뢰도 필터링
  → 정규화 bbox 너비로 포착 조건 검사 및 대상 선택
  → /tob/perception/pumpkin_detection (TargetObservation)
```

`--debug` 지정 시 탐지 노드에서 별도의 디버그 영상 토픽도 발행한다.

## 5. 모듈 책임

### detector.py

- ROS 통신과 독립적인 모델 로딩 및 추론 모듈.
- 시작 시 모델을 한 번 로딩하고 재사용한다.
- 이미지 입력에 대해 원본 영상 기준 박스, 클래스 ID, 신뢰도를 반환한다.
- 잘못된 모델, 이미지 또는 추론 실패를 호출자에게 전달한다.
- 모델 실행 라이브러리와 모델 호환성은 구현 전 확인한다.

### boo_detector_node.py

- `sensor_msgs/msg/CompressedImage` 구독 및 디코딩.
- 원본 영상의 촬영 시각과 `frame_id` 보존.
- 추론 호출, bbox 기반 포착 판정, 대상 선택 및 메시지 변환.
- 탐지 결과와 선택적 디버그 영상 발행.
- 깊이 계산, TF 변환, 추격 행동 및 게임 판정은 수행하지 않는다.

## 6. 탐지 입출력과 메시지

| 항목 | 설계 |
|---|---|
| 입력 토픽 | `/robot1/oakd/rgb/image_raw/compressed` |
| 입력 타입 | `sensor_msgs/msg/CompressedImage` |
| 출력 토픽 | `/tob/perception/pumpkin_detection` |
| 출력 타입 | `tob_interfaces/msg/TargetObservation` |
| source | `boo_camera` |

| 필드 | 탐지 및 포착 조건 통과 | 정상 영상에서 미탐지 또는 포착 조건 미달 |
|---|---|---|
| `header` | 입력 영상의 시각 및 frame_id | 동일 |
| `source` | `boo_camera` | 동일 |
| `detected` | true | false |
| `confidence` | 선택 대상의 신뢰도 | 0 |
| `bbox_center_x/y` | 원본 너비/높이로 정규화한 박스 중심 | 0 |
| `bbox_width/height` | 원본 너비/높이로 정규화한 박스 크기 | 0 |
| `map_valid` | false | false |
| `target_position` | 기본값, 무효 | 기본값, 무효 |
| `distance_m` | 기본값, 무효 | 기본값, 무효 |

탐지 단계에서 위치와 거리는 무효이며 `map_valid=false`일 때 사용해서는 안 된다. 박스는 디코딩된 원본 RGB 영상의 너비와 높이를 기준으로 정규화하며, 모델 내부 리사이즈 좌표를 그대로 발행하지 않는다.

`detected=true`는 모델이 대상을 찾았고 bbox 포착 조건도 만족했다는 뜻이다. 실제 AMCL 거리가 포착 거리 이내임을 보장하지 않으며, 거리 기반 게임 판정은 최종 observation의 유효한 `distance_m`으로 별도 수행한다.

## 7. 대상 선택과 처리 방식 — 검토안

- 대상 클래스와 신뢰도 기준을 통과한 탐지만 사용한다.
- 유한값과 유효 면적을 검사하고 영상 경계로 제한한 bbox를 정규화한다.
- 포착 기준은 `bbox_width = (x2 - x1) / image_width`로 한다. 높이와 면적은 위쪽 잘림에 민감하므로 필수 포착 기준으로 사용하지 않는다.
- 실제 포착 거리 경계에서 대상의 정면·측면 및 카메라 자세별 너비를 측정해 임계값을 결정한다. 대상의 자세에 따라 너비가 달라지므로 bbox를 정확한 미터 단위 거리로 간주하지 않는다.
- 초기 구현은 단일 너비 임계값으로 시작한다. 경계에서 상태가 반복 전환되는 문제가 확인되면 동일 대상 연결 방법을 확정한 뒤 진입·해제 임계값을 구분하는 히스테리시스를 검토한다.
- 클래스·신뢰도·포착 조건을 모두 통과한 후보 중 최고 신뢰도 대상 하나를 선택한다. 최고 신뢰도 후보만 먼저 선택하여 다른 포착 가능한 후보를 누락하지 않는다.
- 화면 위쪽에 닿았다는 이유만으로 포착 처리하지 않는다. 좌우 잘림이나 가림으로 너비까지 감소하면 bbox만으로 근거리 여부를 보장할 수 없으며, 초기 구현은 같은 너비 기준을 적용한다.
- 같은 클래스가 여러 개 검출될 수 있다면 선택 대상이 Pumpkin임을 식별하는 조건을 구현 전에 확정한다. 신뢰도만으로 개체 식별을 보장하지 않는다.
- 단일 처리 흐름으로 시작하고 입력 대기 깊이는 1로 제한한다.
- 입력 속도가 추론 속도를 초과하면 모든 카메라 프레임의 처리를 보장하지 않는다.
- 실제로 처리한 정상 프레임마다 탐지 또는 미탐지 결과를 발행한다.
- 과거 프레임 결과를 새로운 촬영 시각으로 재발행하지 않는다.

## 8. 파라미터 및 실행 옵션

| 항목 | 값 또는 검토 상태 |
|---|---|
| `model_path` | 필수 설정. `config/detectors.yaml`에서 `models/yolo11n_boo.pt` 지정. 상대 경로는 패키지 share 디렉터리 기준이며 절대 경로도 허용 |
| `image_topic` | `/robot1/oakd/rgb/image_raw/compressed` |
| `detection_topic` | `/tob/perception/pumpkin_detection` |
| `source` | `boo_camera` |
| `target_class_id` | 모델 클래스 확인 후 확정 |
| `confidence_threshold` | 0.5 제안, 아직 미확정 |
| `min_bbox_width_ratio` | 신규 포착 너비 임계값. 0보다 크고 1 이하이며 실제 포착 거리·대상 자세별 측정 후 확정; 임의 기본값으로 거리 보장을 하지 않음 |
| `device` | GPU 사용 확정; 라이브러리별 지정 형식 및 GPU 인덱스 확인 필요 |
| `use_sim_time` | 실제 장비에서는 false 제안 |
| `debug_image_topic` | `/tob/perception/debug/image/compressed` |
| 실행 옵션 `--debug` | 지정 시에만 디버그 영상 발행 |

파라미터는 시작 시 읽고 검증하는 방식을 제안한다. 실행 중 모델 교체는 이번 설계 범위에 포함하지 않는다.

GPU를 사용할 수 없는 경우 Warning 경고를 한 뒤, 자동 종료한다. 구체적인 장치 값은 모델 라이브러리와 실행 환경 확인 후 결정한다.

`--debug`는 노드 전용 실행 옵션으로 처리하고 ROS 실행 인자와 분리한다. 디버그를 활성화하는 별도 ROS 파라미터는 두지 않는다. 실제 실행 진입점 등록 후 실행 명령을 확정한다.

## 9. 디버그 영상

- `--debug` 미지정: 디버그 publisher 미생성한다.
- `--debug` 지정: 처리한 원본 RGB 영상에 선택한 대상의 박스, 클래스 및 신뢰도를 표시해 발행한다.
- 미탐지 프레임도 발행하여 정상 영상 입력과 미탐지를 확인할 수 있게 한다.
- 디코딩/추론 실패 프레임은 정상 디버그 결과로 발행하지 않는다.
- 디버그 영상의 header는 입력 영상의 시각과 frame_id를 유지한다.
- 출력 타입은 `sensor_msgs/msg/CompressedImage`이며, 박스와 신뢰도를 표시한 BGR 영상을 JPEG로 압축하여 발행한다. `format`은 `bgr8; jpeg compressed bgr8`이다.
- GUI 창은 필수로 띄우지 않으며 ROS 영상 뷰어에서 확인한다.
- 디버그 영상이 유일한 탐지 결과가 되지 않도록 정식 탐지 토픽은 항상 별도로 발행한다.

## 10. QoS 및 실패 처리

입력 영상과 디버그 영상은 다음 QoS로 설정한다. 
> RELIABLE / VOLATILE / KEEP_LAST / depth=1

| 상황 | 동작 |
|---|---|
| 모델 경로/로딩, 클래스 설정, 필수 파라미터 오류 | 원인을 알리고 시작 중단 |
| GPU 사용 불가 | 원인을 알리고 중단 |
| 정상 영상에서 대상 없음 | detected=false 발행 |
| 대상은 검출됐지만 bbox 포착 조건 미달 | detected=false, 신뢰도·박스는 기본값으로 발행 |
| 디코딩 또는 추론 실패 | 오류 기록, 해당 관측 발행 생략 |
| 카메라 입력 중단 | 과거 결과 재발행 금지; 수신자가 만료 검사 |

## 11. 탐지 구현 전 확인 사항

1. PT 모델의 라이브러리 호환성과 실제 Pumpkin 클래스 ID/이름.
2. GPU 실행 환경, 사용 GPU 인덱스 및 device 지정 형식.
3. 실제 RGB 토픽의 자료형, frame_id, 해상도와 QoS.
4. 대상 선택 정책과 신뢰도 기준의 승인.
5. 디버그 영상 토픽/타입 및 실행 옵션 처리 방식의 승인.
6. 포착 최대 거리와 대상의 자세별 bbox 너비, 위쪽·좌우 잘림 영향 및 `min_bbox_width_ratio`.
7. 두 AMCL 토픽, 공통 지도, 로봇 기준 프레임, 시계 동기화 및 위치 품질 기준.
8. 거리 판정에 허용할 오차·지연과 관측 만료시간·위치 시각 차이 제한.

## 12. 탐지 구현의 예상 수정 범위와 검증

향후 구현 후보: detector.py, boo_detector_node.py, config/detectors.yaml, setup.py, package.xml. 모델/설정 설치 항목과 실행 진입점을 포함하되, 정확한 변경 내용은 구현 전 승인받는다. 현재는 이 설계 문서만 작성한다.

탐지 구현 후 확인할 항목:

- 기본 모델 및 지정 모델 경로로 GPU 로딩 가능.
- 실제 압축 영상에서 대상 탐지와 미탐지 구분.
- 정규화 박스, 원본 header 및 map_valid=false 확인.
- 카메라 중단과 처리 오류가 정상 미탐지로 위장되지 않음.
- --debug 지정 시 영상 토픽 발행, 미지정 시 디버그 publisher 없음.
- 정식 탐지 결과와 디버그 영상의 시각/박스 일치.
- 탐지 토픽의 자료형과 발행 필드가 실제 TargetObservation 정의와 일치함.
- bbox 너비 임계값 전후, 위쪽 잘림, 좌우 잘림 및 후보가 여러 개인 경우의 포착 판정 확인.
- depth·AMCL 값의 유무가 bbox 기반 `detected` 판정을 바꾸지 않음.

## 13. AMCL 기반 위치·거리 계산 및 후속 검증

### 13.1 위치 계산 방식과 데이터 연결

우선 `tob_localization/target_localizer_node.py`에서 탐지 결과와 두 로봇의 `/<ns>/amcl_pose`를 결합한다. 두 위치를 같은 지도 좌표계와 로봇 기준점으로 맞춘 뒤 평면 거리를 계산한다. depth 및 CameraInfo는 이 거리 계산의 필수 입력이 아니다.

```text
/tob/perception/pumpkin_detection (TargetObservation)
  → target_localizer_node.py
      + Boo의 amcl_pose
      + Pumpkin의 amcl_pose
      + 필요한 경우 관측 시각에 대응하는 TF
  → 위치의 좌표계·시각·품질 검사
  → Pumpkin 지도 위치 및 두 로봇 기준점 사이 평면 거리
  → /tob/target/observation (TargetObservation)
```

RGB bbox로 포착 여부를 결정하고, 포착한 대상에만 지도 위치와 거리를 연결한다. `detected=false`인 관측에는 Pumpkin의 최신 위치를 새로운 추격 목표로 연결하지 않는다. 위치 검증 실패는 `detected`를 바꾸지 않고 `map_valid=false`로 표현한다.

### 13.2 AMCL 위치 및 TF 연결 조건

- 위치 입력 타입은 `geometry_msgs/msg/PoseWithCovarianceStamped`를 사용하며 실제 토픽 타입을 확인한다.
- 두 로봇의 실제 AMCL 토픽, QoS, 지도와 기준 프레임을 확인한다. namespace만으로 TF 프레임이 구분된다고 가정하지 않는다.
- 동일한 지도 좌표계와 기준점을 사용하면 두 위치를 직접 계산하며 불필요한 TF 변환을 하지 않는다.
- 지도나 기준점이 다르면 검증된 변환을 사용한다. `frame_id` 문자열이 둘 다 `map`이어도 서로 다른 지도라면 직접 비교하지 않는다.
- TF는 좌표계 변환에 사용하며 AMCL 오차를 줄이는 수단으로 간주하지 않는다. 필요한 시각의 변환이 없으면 최신 TF로 임의 대체하지 않는다.
- RGB 촬영 시각을 유지하고 두 로봇이 같은 시간 기준을 사용하는지 확인한다.
- 제한된 위치 버퍼에서 RGB 관측 시각에 가장 가까운 각 로봇의 위치 샘플을 선택하고, 각각의 관측 시각 차이·두 샘플 사이 시각 차이·자료 만료시간을 검사한다. 초기 구현은 오래된 위치의 외삽이나 별도 융합 필터를 추가하지 않는다.
- 위치·방향·covariance의 유한값과 유효성, 위치 불확실성의 허용 기준을 검사한다. 필요한 TF 변환이 있다면 covariance도 같은 기준으로 해석한다.
- 위치 점프·재초기화에 대한 검사 기준을 정하고, 이상 샘플은 정상 거리 계산에 사용하지 않는다. 낮은 covariance만으로 실제 정확도를 보장하지 않는다.
- 미포착, 위치 누락·만료·시각 불일치·품질 미달 또는 필요한 TF 실패 시 `map_valid=false`로 전달한다.
- 감지 상실 또는 위치 검증 실패 시 과거 위치·거리를 현재 관측처럼 발행하지 않는다.

### 13.3 위치 및 거리 메시지 규칙

- `header`는 RGB 원본 관측 시각과 frame_id를 유지하고 `source` 및 탐지 필드를 그대로 전달한다.
- `detected=true`이고 두 로봇 위치가 모두 유효할 때만 `map_valid=true`로 설정한다.
- `target_position`에는 공통 `map` 좌표계의 Pumpkin 기준점 위치를 넣는다. 내부 header에는 사용한 Pumpkin 위치 샘플의 시각과 공통 지도 frame_id를 기록한다.
- `distance_m = hypot(pumpkin_x - boo_x, pumpkin_y - boo_y)`로 두 로봇 기준점 사이의 평면 거리를 계산한다. 표면 사이 간격, 카메라 깊이 또는 LiDAR range로 의미를 바꾸지 않는다.
- `map_valid=false`이면 `target_position` 및 `distance_m`은 기본값으로 두고 사용하지 않는다. 거리 0을 유효한 근접 측정으로 해석하지 않는다.
- 현재 `TargetObservation.msg`의 필드로 우선 구현하며 depth 전용 거리·유효성 필드는 추가하지 않는다. AMCL covariance는 위치 계산 단계에서 검증한다.
- 거리 기반 체포 조건과 유지시간은 게임 판정에서 처리한다. bbox 포착 임계값과 체포 거리 임계값은 별개이다.
- 이 변경은 `docs/interfaces.md`의 Level 1 거리 정의와 일치한다. `target_localizer_node.py`의 현재 깊이 기반 지침 및 관련 설정·테스트는 실제 구현 시 AMCL 방식에 맞춰 변경해야 한다. 이번 수정은 본 설계 문서에 한정한다.

### 13.4 정확도 검증 및 구현 전 결정 사항

- 포착 최대 거리, bbox 너비 임계값, AMCL 토픽·QoS·기준 프레임, 위치 버퍼 길이, 자료 만료시간·시각 차이 제한, covariance 및 위치 점프 기준은 구현 전에 확정한다. 임의 값을 실제 장비에서 검증한 값처럼 사용하지 않는다.
- 실제 거리 기준점과 허용 오차·지연을 정한 뒤, 거리 판정 경계 전후에서 정지·접근·후퇴·회전 중 추정 거리와 실측 거리를 비교한다.
- 두 AMCL 위치의 오차와 시간 불일치가 상대 거리 오차에 함께 영향을 준다. 평균뿐 아니라 최대 오차와 지연, 임계값 주변의 오판정 여부를 확인한다.
- 대상 미포착, 한쪽 AMCL 중단, 오래된 위치, 시각 불일치, 큰 covariance, 위치 점프·재초기화, 서로 다른 지도 및 필요한 TF 실패를 검증한다.
- bbox 포착은 유지되지만 위치가 무효인 경우 `detected=true`, `map_valid=false`로 구분되는지 확인한다.
- 판정 경계의 불확실성 처리와 연속 유지시간은 실측 결과를 기준으로 게임 규칙 담당과 확정한다. 시간 필터나 유지시간으로 체계적인 위치 오차가 해결된다고 가정하지 않는다.

### 13.5 AMCL 정확도가 부족할 때의 후속 대안

- AMCL 방식이 허용 오차·지연을 만족하지 못할 때 카메라 detection과 연결한 2D LiDAR 또는 보정된 RGB 기반 거리 추정을 검토한다. 자동 fallback이나 센서 융합은 우선 구현에 포함하지 않는다.
- 2D LiDAR는 최소 측정 거리와 스캔 높이가 상대 로봇 형상에 맞는지 확인한다. 촬영 시각과 스캔 시각을 맞추고 카메라–LiDAR TF 및 CameraInfo로 bbox에 대응하는 점군 후보를 찾는다.
- bbox 방향의 최소 range를 곧바로 상대 로봇 거리로 사용하지 않는다. 벽·다른 장애물과 대상을 구분할 수 없거나 점이 부족하면 측정을 무효로 처리한다.
- LiDAR 및 depth는 대상 표면을 측정하므로 로봇 기준점 거리와의 관계를 정의해야 한다. 표면 거리를 기존 `distance_m`에 그대로 대입하지 않는다.
- depth를 다시 사용할 경우 RGB 정렬·시각 동기화, ROI 유효 픽셀 비율·분산 및 장비의 최소 측정 범위를 검증한다. 0.5m 이내의 불안정을 필터만으로 해결할 수 있다고 가정하지 않는다.
- 다른 거리 소스를 채택할 때 거리 의미·유효성 및 필요한 메시지 변경을 별도 검토한다.
- 처리 주기 제한, 병렬 추론 또는 추적 기능은 성능 측정 후 필요성이 확인되면 별도로 검토한다.

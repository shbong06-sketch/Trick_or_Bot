2. 🔴 **2부는 순서를 지킨다: 시뮬레이터(A) → AMCL 위치 확인 → 내비게이션(B) → 관측 발행(D).** 앞 단계의 ✅가 나오기 전에 다음 단계로 가지 않는다.
3. 🔴 **2-3에서 `/robot1/amcl_pose`가 3분 안에 안 나오면 멈추고 `sim_*.txt` 로그를 Claude에게 알린다.** 계속 기다리지 않는다. (Claude 환경에서는 로봇2 스폰과 map_server 활성화에서 멈췄다.)

5. 🔴 **시험이 끝나면 터미널 로그와 bag을 `boo_nav/result_boo_nav/`에 저장한 채로 둔다.** 이 파일이 Claude가 읽는 증거다.
6. 🔴 **시험을 끝내거나 다시 하기 전에 남은 프로세스를 정리한다 (2-0).** 이전 실행의 노드가 남으면 컨트롤러 등록을 막는다.

## 2부. Gazebo 통합 시험 (실제 Nav2 사용) — 사용자 실행

### 2-0. 🔴 필수 — 남은 프로세스 정리 (시험 전마다)

```bash
source ~/Trick_or_Bot/boo_nav/tools/env_sim.sh
ps -eo pid,args | grep -E "gz sim|/opt/ros/jazzy/lib/|turtlebot4_ws/install" | grep -v grep
ros2 daemon stop; fastdds shm clean
```

✅ `ps` 줄에 아무것도 안 나와야 한다. 나오면 그 PID를 `kill <PID>`로 종료한다.
⚠️ `pkill -f`는 쓰지 않는다. 입력한 명령 자체와 이름이 겹치면 터미널이 같이 종료된다.

### 2-1. 터미널 A — 시뮬레이터 🔴 필수

```bash
source ~/Trick_or_Bot/boo_nav/tools/env_sim.sh
cd ~/Trick_or_Bot
ros2 launch boo_nav/sim/launch/pumpkin_run_sim_boo.launch.py \
  2>&1 | tee -i boo_nav/result_boo_nav/log_boo_nav/sim_$(date +%y%m%d_%H%M%S).txt
```

기본은 Gazebo 창이 뜬다. 창 없이 하려면 명령 끝에 `headless:=true`를 붙인다. 약 1~3분 걸린다. **이 터미널은 시험이 끝날 때까지 켜 둔다.**

### 2-2. 터미널 C — 위치 확인 🔴 필수 (A를 켠 뒤)

토픽이 뜰 때까지 기다린다. (한 번만 조회하면 시뮬레이터가 덜 떴을 때 `Could not determine the type for the passed topic` 오류가 난다. 토픽이 아직 없다는 뜻이다.)

```bash
source ~/Trick_or_Bot/boo_nav/tools/env_sim.sh
ros2 daemon stop      # 이전 실행의 오래된 정보를 지운다
timeout 180 bash -c 'until ros2 topic list 2>/dev/null | grep -q "/robot1/amcl_pose"; do echo "대기 중: AMCL이 아직 안 떴다"; sleep 3; done'
ros2 topic echo --once /robot1/amcl_pose --field pose.pose.position
```

✅ `x:`, `y:` 값이 나오고 **x ≈ -3.05, y ≈ -3.30** (Boo 시작 위치) 부근이어야 한다.
⚠️ **3분이 지나도 `대기 중`만 나오면 2-3으로 가지 말고 중단한다** (🔴 3번). 아래 두 줄의 출력을 터미널 A 로그(`sim_*.txt`)와 함께 알린다.

```bash
ros2 node list | grep robot1
ros2 topic list | grep robot1 | head -20
```

⚠️ 아무것도 안 나오면 이 터미널이 도메인 77이 아니라는 뜻이다. 첫 줄 `source ... env_sim.sh`에서 `[env_sim] ROS_DOMAIN_ID=77`이 보였는지 확인한다.

---

### 2-3. 터미널 B — Nav2 + Boo 컨트롤러 🔴 필수

```bash
source ~/Trick_or_Bot/boo_nav/tools/env_sim.sh
cd ~/Trick_or_Bot
ros2 launch tob_bringup navigation.launch.py namespace:=robot1 use_sim_time:=true \
  control_params:=$HOME/Trick_or_Bot/boo_nav/config/control_sim.yaml \
  2>&1 | tee -i boo_nav/result_boo_nav/log_boo_nav/nav_$(date +%y%m%d_%H%M%S).txt
```

(`control_sim.yaml`은 게임 상태·안전 상태 확인을 끈 시험용 설정이다. 실제 운용에는 쓰지 않는다.)

✅ 로그에 `boo_controller 시작: 순찰 지점 2개` 가 나와야 한다.
✅ 터미널 C에서 `ros2 action list | grep navigate_to_pose` 로 `/robot1/navigate_to_pose` 가 보여야 한다.
⚠️ `Nav2 목표 N 결과: NO_SERVER` 가 반복되면 Nav2가 아직 활성화되지 않은 것이다. 30초 기다려도 같으면 로그(`nav_*.txt`)를 Claude에게 알린다.

### 2-4. 터미널 C — 순찰 확인

```bash
source ~/Trick_or_Bot/boo_nav/tools/env_sim.sh
ros2 topic echo /tob/boo/state --field behavior
```

✅ `1`(PATROL)이 나오고 Boo가 (-3.0, -3.25)와 (-3.0, -0.75) 사이를 왕복한다(왼쪽 통로를 위아래로). Gazebo 창으로 확인한다.
⚠️ 계속 `0`(IDLE)이면 컨트롤러가 이동을 막고 있다. `control_params`로 `control_sim.yaml`을 넘겼는지 2-3 명령을 다시 본다.

### 2-5. 터미널 D — 가짜 펌킨 관측 발행 (추격 시험)

⚠️ **여기에 쓰는 좌표 `-2.75 -0.5`는 `holloween_boo` 지도에서 빈 공간(벽까지 0.5 m 이상)으로 확인한 점이다. 다른 값으로 바꾸려면 장애물 위가 아닌지 먼저 확인한다.**

```bash
source ~/Trick_or_Bot/boo_nav/tools/env_sim.sh
cd ~/Trick_or_Bot
python3 boo_nav/tools/obs_pub.py -2.75 -0.5 --sim-time
```

✅ 터미널 C의 값이 `1` → `2`(SUSPECT, 멈춤) → 약 3초 뒤 `3`(CHASE, 이동 시작)으로 바뀐다.
✅ Boo가 (-2.75, -0.5)에서 약 0.45 m 떨어진 곳까지 가서 멈춘다 (정지 거리).

멈춘 뒤 이 터미널에서 `Ctrl+C`로 발행을 끝낸다. ✅ 약 1~2초 뒤 `4`(SEARCH) → `1`(PATROL)로 돌아온다.

## 알려둔 한계

- 순찰 지점 (-3.0, -3.25), (-3.0, -0.75)와 정지 거리 0.45 m는 임시값이다. 순찰 지점이 확정되면 `config/control.yaml`을 바꾼다.
- Boo 시작 위치(-3.05, -3.30, 위쪽)는 옛 시뮬레이션 화면에 사용자가 표시한 자리를 `holloween_boo` 좌표로 옮긴 값이다(근사). 위치가 어색하면 `boo_nav/sim/level1_sim.yaml`의 `boo_start`를 고친 뒤 월드는 다시 만들 필요 없이 launch만 다시 켠다.
- 사탕·탈출문 표식은 월드에 넣지 않았다(아직 구현 대상이 아님).
- `nav2.yaml`의 최대 속도는 Lv1 술래 속도 0.12 m/s로 낮춰 놓았다. `[tob]` 주석이 붙은 세 줄이다.
- 이 단계는 **실제 탐지 노드 없이 가짜 관측**으로 추격을 시험한다. 탐지·위치 계산 노드가 준비되면 `obs_pub.py` 대신 그 노드를 쓴다.

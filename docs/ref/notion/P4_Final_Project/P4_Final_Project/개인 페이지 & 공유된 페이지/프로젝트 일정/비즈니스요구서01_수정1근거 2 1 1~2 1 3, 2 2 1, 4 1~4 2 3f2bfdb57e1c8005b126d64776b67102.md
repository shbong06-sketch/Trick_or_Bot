# 1. Executive Summary

## 1.1 대상 고객과 상황

우선 고객은 **시즌 체험 콘텐츠를 외주 또는 자체 제작하는 테마파크·실내 어뮤즈먼트 운영자** 한 업종으로 한정한다. 방탈출·VR 아케이드·키즈카페·로봇 체험관은 요금대·안전 요건·규제 경로(13.2)가 달라 확장 후보로만 둔다(버전 2·3 문서는 교육 체험·게임사 이벤트를 각각 별도 사업으로 다룬다). 국내 대형 테마파크는 매년 9~11월에 좀비·호러 콘셉트의 할로윈 시즌을 운영하며, 유료 호러 메이즈를 별도 판매하는 사례가 확인된다 [S-21, S-22]. 해외에서는 실물 로봇을 플레이어가 조종하는 배틀 아레나가 상설(두바이·중국)·대여(영국, FPV) 형태로 확인된다 [S-01, S-02, S-03]. 일본에서는 이벤트 출장형 실기 로봇 배틀 콘텐츠가 회전율 수치(1일 최대 108~120명)와 함께 파트너 모집 중이다 [S-36]. 우선 이용 시나리오는 시즌 한정 체험형 어트랙션이며, 국내 운영자의 도입 의향·회전율 요구·구매 구조는 추가 확인한다.

**근거: 2.1.1~2.1.3, 2.2.1, 4.1~4.2.**

## 1.2 핵심 문제

시즌 호러 콘텐츠는 배우·세트 중심이라 인건비와 안전 관리 부담이 크고, 로봇 체험관은 관람·시연 위주라 "직접 조종하는 게임"이 사실상 비어 있다 [S-15, S-16, S-17]. 실물 로봇 게임의 상용 사례는 대부분 격투·레이싱이며, **AI 로봇이 플레이어 로봇을 자율 탐지·추격하는 스텔스/술래잡기형 상용 서비스는 본 조사에서 확인되지 않았다**. 이는 차별점이자 "왜 아무도 안 했는가"를 설명해야 하는 리스크다(지연·인식 오류·끼임·회전율, 9.3).

**근거: 2.1.3, 2.3.1~2.3.2.**

## 1.3 제안 솔루션

「AMR 기반 설치형 비대칭 스텔스 게임」을 제안한다. 할로윈 테마 소형 맵에서 술래 AMR(AI)은 순찰→의심→추적→체포→수색→복귀 상태기계로 자율 동작하고, 생존자 AMR은 플레이어가 웹 UI에서 1인칭 카메라 영상과 미니맵을 보며 키보드로 조종한다. 생존자는 제한 시간 안에 열쇠(지정 지점 체류 또는 발전기 게이지)를 모아 탈출하며, 레벨이 오르면 열쇠 수·제한 시간·맵 은폐물·아이템이 바뀐다. 술래는 생존자 로봇 위에 올린 호박 마커를 카메라로 탐지한다. 관리자 UI는 탑뷰 지도·로봇 상태·텔레옵 복구를 제공한다.

**범위·업무 흐름: 3장, 6장.**

## 1.4 기대 가치

운영자 관점의 기대 가치는 (a) 배우 없이 반복 가능한 시즌 체험 콘텐츠, (b) 테마 교체(호박→다른 IP)로 비시즌 재활용, (c) 1인 직원 운영. 플레이어 관점은 "실물이 움직이는 스릴"과 리더보드 경쟁이다. 본 문서 시점에서 대안 대비 우위가 확인된 가치는 없으며 전부 검증 대상이다. 다만 실물 로봇은 가상 게임보다 속도가 느리고 회전율이 낮으므로, 가치는 **체험 1회당 만족도·재방문 의향**과 **운영 인시**로 측정하며 "가상 게임보다 재미있다"는 주장은 하지 않는다.

**가치·경제성 검증 기준: 2.3.4, 4~5장.**

## 1.5 이번 프로젝트의 검증 목표

지정 실내 맵(판자 벽·나무 모양 은폐물)에서 Level 1(열쇠 3개·기본 순찰·시간 제한)을 구현하고 Level 2(발전기 게이지·웹캠 노출 시 술래 이동·아이템 1종 이상)를 목표로 한다. 검증 항목은 술래의 호박 탐지 정확도, 체포 판정의 오판·누락, 조종 지연, 1세션(약 3~5분) 무개입 완주율, 플레이테스트 만족도이다. 목표 수치는 기초 시험 후 인수 시험 전에 확정한다.

**검증 지표·인수 기준: 5장, 10장.**

## 1.6 결론과 조건

실물 로봇 LBE(location-based entertainment)와 시즌 호러 콘텐츠의 시장 존재는 공개 자료로 뒷받침되나 수요는 미확인(인터뷰·설문 0건)이므로, 보유 장비로 게임 루프 전체(탐지→추격→판정→UI)를 연결하는 프로젝트 검증을 추진한다. 사업화 판단에는 국내 운영자의 도입 의향, 회전율·가격, 등급분류 또는 유기기구 규제 경로(13장)에 대한 증거가 더 필요하다. 시험은 보유 TurtleBot4 2대의 속도·배터리·카메라 성능 범위에서 수행하며, 대형 맵·다중 플레이어·상설 운영 성능은 이번 시험의 달성 결과로 주장하지 않는다.

**수행기간·사업비:** 과정 일정 5~10차시(설계 1차시, 개발 4차시, 발표 1차시). 사업비는 교육기관 제공 장비·시설을 사용하며, 맵 소품(판자·나무 모형·호박 마커)만 소액 자비 구매 가능성이 있다(16장).

**추진 조건·추가 검증: 4.7, 8~10장, 13장.**

### 2.1.1 고객 업무

국내 대형 테마파크는 9~11월 할로윈 시즌에 좀비 퍼포먼스·워크스루 호러 어트랙션을 매년 신규 제작하며, 에버랜드는 자유이용권과 별도로 1만 원을 받는 유료 호러 메이즈를 운영하고 중도 포기율 5.5%를 공포 강도의 지표로 홍보했다 [S-21]. 롯데월드는 중국 관광객 감소 국면에서 호러 할로윈을 집객 수단으로 강화했다고 밝혔다 [S-22]. 이 업무는 (1) 콘텐츠 기획·세트 제작, (2) 배우·안전요원 채용·운영, (3) 시즌 종료 후 철거로 구성된다. 본 사업은 (1)~(3)을 "로봇 아레나 + 소프트웨어 레벨 교체"로 대체·보완하는 공급자 위치를 노린다.

이 목록은 대안의 존재와 범위를 설명한다. 조사 범위는 한국어·중국어·일본어·영어 공개 자료이며 그 밖의 언어권은 미조사다. 네 언어권 모두에서 "AI 술래 + 플레이어 조종 생존자" 조합의 상용 사례는 확인되지 않았고, 가장 가까운 것은 일본의 이벤트 출장형 로봇 배틀(S-36)과 중국의 아케이드형 로봇 격투(S-02)다. 국내 소형 체험 업종(레이저태그·서바이벌, 방탈출, VR 아케이드, 호러 체험 카페, RC·드론 레이싱장)은 명칭만 확인했고 출처·수치는 [확인 필요]이며, RIOT Arena의 현재 영업 여부는 추가 확인이 필요하다. "국내에 대안이 없다"는 표현 대신 "직접 조종·자율 술래 조합의 상용 사례가 확인되지 않았다"로 한정한다.

### 2.1.4 적용 환경

사업 대상은 **관객 동선과 물리적으로 분리된 실내 소형 아레나**이다. 플레이어는 아레나 밖 단말에서 조종하므로 로봇과 사람이 같은 공간에서 움직이지 않는다. 이는 안전·규제 측면에서 유리하지만(13장), 직원이 끼임 복구를 위해 아레나에 들어가는 순간은 예외로 관리한다.

#### 적용 판단

초기 검증은 조명을 통제할 수 있는 교육기관 실내 공간, 접이식 판자 맵, 관객 미입장 조건에서 수행한다. 어두운 호러 조명과 다수 관객이 있는 실제 테마파크 환경의 성능은 별도 실증이 필요하다.

### 2.2.3 사업 기준선과 대안 비교의 선정

**사업 기준선:** 운영자가 현재 사용하는 시즌 체험 콘텐츠(배우 기반 워크스루 또는 영상 시뮬레이션)의 세션당 비용·회전율. 공개 자료로는 확정할 수 없어 운영자 인터뷰(4.7)로 확보한다.

**프로젝트 시험 기준선:** 같은 맵에서 **사람이 술래 로봇을 텔레옵으로 조종하는 조건**을 비교군으로 둔다. 이 비교군은 (1) AI 술래의 상태기계가 사람 술래 대비 재미·긴장감을 어느 정도 재현하는지, (2) 직원 1명 운영 가설이 AI 없이도 성립하는지를 가른다. 가상 게임(DBD)은 비교군으로 두지 않는다.

## 3.4 To-Be

1. 진행요원이 관리자 UI에서 레벨 지도를 로드하고 로봇 2대의 위치·배터리를 확인한다.
2. 플레이어가 닉네임을 입력하고 레벨을 선택해 게임을 시작한다.
3. 술래 AMR이 순찰을 시작하고, 생존자 AMR 1인칭 영상·미니맵·제한 시간이 플레이어 화면에 표시된다.
4. 플레이어가 열쇠 지점(또는 발전기 지점)으로 이동해 체류·게이지를 채운다. 웹캠에 노출되면 술래가 해당 위치로 이동한다.
5. 술래가 호박을 탐지하면 의심 게이지가 오르고, 만충 시 추적한다. 근접 시 플레이어 단말에 비프/심장 소리가 난다.
6. 체포 판정 또는 시간 초과 시 게임오버 화면, 열쇠 완료 후 탈출 지점 도달 시 클리어 화면과 리더보드가 표시된다.
7. 끼임·통신 이상·안전 신호 시 안전 에러 화면이 뜨고, 진행요원이 관리자 UI 텔레옵으로 복구한 뒤 세션을 재개 또는 재시작한다.
8. 세션 로그(시간·판정·개입)가 저장된다.

## 4.3 현재 방식의 비용 구조

**세션당 운영비 = 직원 인시 × 인건비 + 전력·소모품 + 세션에 귀속되는 장비 감가 + 복구·재작업 비용**

회전율이 핵심 변수다. 1인 세션 3~5분, 세션 간 전환 1분을 가정하면 시간당 약 10세션이며, Gamebox형 2~6인 룸 대비 시간당 체험 인원이 적다. 요금이 같다면 매출은 열세이므로, 가치는 (a) 설치 면적·투자비가 작다는 점과 (b) 대기열 관람(구경하는 재미)에서 찾아야 한다. 이는 가정이며 수치는 미확인.

## 10.1 공통 시험 조건

- 장비·소프트웨어·모델·레벨 YAML 버전을 기록한다.
- 맵 배치·조도·Wi-Fi 조건을 기록한다.
- 체포·열쇠 판정 조건을 시험 전에 고정한다.
- 세션 시작·종료·판정·개입 시각을 로그로 남긴다.
- 실패 세션을 제외하지 않고 원인을 분류한다.
- 아레나 내 사람 미입장, 복구 시 e_stop 적용을 기록한다(13.1).

## 10.2 미달성 처리

- 필수 요구사항 미달: 수정 후 재시험
- Level 2 미완성: Level 1 인수와 분리하여 "목표 미달성"으로 표시
- KPI 미달: 결과 공개 후 목표 조정 또는 조건부 수용
- 플레이테스트 열세: AI 술래를 비용 절감 수단으로 재포지셔닝(4.6)

# 11. Example Use Cases

## Case1 — Level 1 정상 세션

- **사용자와 목적:** 플레이어가 열쇠 3개를 모아 탈출한다.
- **시작 조건:** 로봇 2대 대기 위치, 배터리 확인, 아레나 무인.
- **정상 흐름:** 닉네임·레벨 선택 → 시작 → 술래 순찰 → 플레이어 이동·열쇠 획득 → 근접 경고음 → 은폐 → 열쇠 3개 완료 → 탈출 지점 → 클리어·리더보드
- **예외 흐름:** 호박 탐지→게이지 만충→추적→체포 시 게임오버. 시간 초과 시 게임오버.
- **관련 요구사항:** BR-T01~04, 06~07, 11, 13

## Case2 — 끼임 복구

- **사용자와 목적:** 진행요원이 끼인 로봇을 복구하고 세션을 재개한다.
- **시작 조건:** 생존자 또는 술래가 은폐물 사이에서 N초 이상 정지.
- **정상 흐름:** 안전 에러 화면 → 게임 일시정지 → 관리자 UI 텔레옵으로 이동 → 재개 또는 재시작권 부여
- **예외 흐름:** 텔레옵 불가 시 e_stop 후 직원 진입·수동 이동, 세션 무효.
- **관련 요구사항:** BR-T08~09, 12

# 17. Glossary

- 술래(살인마) AMR: AI가 조종하는 추격 로봇. 상용 문서에서는 "술래"로 통일.
- 생존자 AMR: 플레이어가 조종하는 로봇. 상단에 호박 마커 탑재.
- 의심 게이지: 술래가 호박을 관측한 거리·시간에 따라 누적되는 값. 만충 시 추적 전환.
- 체포: 사전 고정 조건(게이지·거리·시간, 선택적 접촉)으로 판정되는 게임오버 사건.
- 열쇠·발전기: 레벨 1은 지점 도달, 레벨 2는 체류 또는 웹캠 노출 시간으로 채우는 진행도.
- 안전 에러 화면: 끼임·통신 이상·hazard 신호 시 플레이어에게 표시되는 일시정지 화면.
- 개발 모드: 관리자 UI에서 술래를 수동 조종하는 모드. 비교군 시험과 디버깅용.
- 프로젝트 시험 기준선: 사람 텔레옵 술래 비교군(2.2.3).
- LBE(location-based entertainment): 테마파크·아케이드·체험 공간 등 물리 장소에서 제공되는 체험형 엔터테인먼트.

#### **레퍼런스 사례 1: Dead by Daylight (비대칭 대전 장르의 기준작)**

- Behaviour Interactive가 개발한 1 대 4 비대칭 멀티플레이 호러 게임. 6,000만 장 이상 판매, 누적 플레이어 7,000만 명(2026-06), 2025년 신규 플레이어 600만 명 이상, 최근 12개월 매출 50% 이상 증가 (2차). 출시 때 예상은 약 30만 장이었다. [B-01, B-02]
- 스토어와 배틀패스를 가진 **라이브서비스** 모델로 전환해 10년간 지속. [B-01, B-02]
- 시사점: (1) 비대칭 규칙(킬러의 추격 대 생존자의 임무 수행·은신)이 장기 재미를 만든다. (2) 수익은 1회 판매가 아니라 콘텐츠 갱신에서 나온다.

#### **레퍼런스 사례 2: 실물 로봇 게임의 명암 (Anki, Mario Kart Live)**

- Anki Drive/Overdrive(2013~)는 모바일 앱 + 실물 로봇 자동차의 대전. Cozmo 같은 로봇 캐릭터 제품도 냈지만 2019-04 파산했고, 2019-12 Digital Dream Labs가 자산을 인수했다. 2024-09 미국 펜실베이니아 법무장관이 주문 미이행·환불 불이행으로 DDL을 제소했다 (2차). [B-03, B-04]
- Mario Kart Live: Home Circuit은 카메라 RC 카트의 영상에 아이템·경쟁자를 AR로 얹는 방식 (2차). [B-05]
- 시사점: 실물 로봇 게임은 몰입감이 강점이지만, 하드웨어 비용과 1회 판매 구조가 약점이다. 본 시스템은 **로봇 2대로 한 아레나를 반복 운영**하는 설치형으로 비용 구조를 달리한다.
- [https://www.youtube.com/watch?v=66QnPKDJZkg](https://www.youtube.com/watch?v=66QnPKDJZkg)

#### **레퍼런스 사례 3: 스텔스 게임 AI의 표준 구조**

- 스텔스 장르(Metal Gear Solid, Splinter Cell, Thief)의 경비병 AI는 대체로 **순찰 → 의심 → 경계/추적 → 수색 → 복귀**의 상태기계(FSM)로 짠다. 시야에 들어오면 즉시 발각이 아니라 **의심 게이지**가 오르며, 시야에서 사라지면 수색 후 순찰로 돌아간다. 현대 게임은 게이지에 감쇠를 두어 플레이어가 만회할 수 있는 "봐주는 구간"을 둔다 (2차). [B-07, B-08]
- 시사점: 본 게임의 살인마 상태 전환(순찰·의심·추적·체포·수색·복귀)은 새로 만든 것이 아니라 검증된 설계 관행을 따른다.

## **8. 규칙·제약**

- AI Object Detection을 사용한다.
- AMR(TurtleBot4) 2대를 사용한다.
    - 안전 모드 최대 속도 0.31 m/s, 배터리 2.5~4.0시간 (공식, B-11)
- ROS2를 사용한다.

## **13. 용어**

- AMR: 자율 이동 로봇 · FSM: 유한 상태기계 · SLAM: 지도 작성과 위치 추정 · Nav2: ROS2 자율주행 스택
- 비대칭 대전: 진영마다 역할·능력·목표가 다른 대전 방식 · 라이브서비스: 출시 후 콘텐츠를 지속 갱신하며 수익을 내는 운영 방식 · LBE: 위치 기반 엔터테인먼트
- 살인마: 순찰·추적하는 AI 로봇 · 생존자: 플레이어가 조작하는 로봇 · 발전기: 지정 구역에 일정 시간 머물러야 하는 게이지 지점 · 의심 게이지: 살인마가 생존자를 보는 거리·시간에 따라 오르는 값
- BR-C / BR-T / BR-R: 상업·경제 / 기술·운영 / 규칙 요구 · KPI: 핵심성과지표

## **15. 참여 인력**

팀원 수와 이름은 `[팀 결정 대기]`이며, 역할 슬롯은 다음과 같다.

| 역할 | 업무 |
| --- | --- |
| R1 게임 설계·통합 | 규칙·레벨 설계, 문서 통합, 결정 관리 |
| R2 살인마 AMR | 순찰, 의심 게이지, 추적, 수색 상태기계, 주행 |
| R3 생존자 AMR·영상 | 조작 입력, 1인칭 영상 전송, 경고 반응 |
| R4 지각 | 호박 마커 detection, 웹캠 구역·노출 판정 |
| R5 서버·데이터 | 게임 상태, 공유 데이터, 리더보드 |
| R6 사용자 UI | 레벨 선택, 게임 화면, 게임오버·클리어 |
| R7 관리자 UI | 탑뷰 지도, 직접 제어, 비상 정지 |
| R8 실측·QA·문서 | 시험 절차, 로그·bag 분석, 시연 영상 |
- 인원이 적으면 R5~R7을 합치고, 많으면 R2·R3에 보조를 둔다.

# 1. Executive Summary

## 1.1 대상 고객과 상황

잠재 고객은 새로운 체험형 게임이나 비대칭 추격·탈출 장르에 관심이 있는 현장 방문객이다. 행사·전시·팝업·상설 체험 공간을 활용 후보로 두며, 플레이어는 로봇을 조작하고 관람객·동행인은 실제 추격을 관람한다.

시설·행사 운영 주체는 체험 콘텐츠의 도입 구매자 후보다. 목표 고객의 세부 특성, 가격과 구매 수요, 시설의 도입 의사는 아직 확인되지 않았다.

## 1.2 핵심 문제

본 프로젝트는 실물 상호작용, 아레나 내부 이동 없이 참여하는 방식, 동행인이 함께 관람하는 경험에 대한 수요 가능성을 다룬다. 운영 측에서는 안내·초기화·복구에 따른 반복 제공 부담을 검토한다.

기존 연구와 현장 체험 자료는 이러한 경험·운영 과제의 근거로 삼는다.

## 1.3 제안 솔루션

3 m × 3 m의 주행 아레나에서 TurtleBot4 기반 생존자·술래 로봇 각 1대가 추격·탈출 게임을 수행한다. 플레이어는 조작석의 웹 화면으로 생존자를 조작하여 열쇠 수집과 탈출을 시도하고, 술래는 AI 관측 결과와 확정된 규칙에 따라 행동한다.

플레이어 화면에는 술래 위치를 표시하지 않고 자기 인근의 장애물·아이템 등 제한된 정보를 제공한다. 관람객은 실물 추격과 역할·목표 안내를 함께 볼 수 있다. 운영자에게는 전체 관제와 시작·중단·초기화 기능을 제공한다. 로봇 표시 오브제와 아이템 표시용 천장 부착 오브제 등으로 테마를 구성한다.

## 1.4 기대 가치

플레이어에게는 로봇 조작으로 참여하는 실물 게임 경험을, 동행인에게는 실제 공간에서 펼쳐지는 추격 관람 경험을 제공한다. 운영자에게는 회차 준비·중단·초기화를 관리할 수 있는 반복 제공형 콘텐츠를 제안한다.

초기 경제성 분석은 플레이어의 회차 이용료를 운영 주체의 매출로 계산한다. 실물 경험의 구매 기여와 운영 부담 상쇄는 가치 가설이며, 아레나 면적만으로 전체 설치 면적이나 비용 절감을 주장하지 않는다.

## 1.5 이번 프로젝트의 검증 목표

기본 레벨 1개에서 조작·안내·열쇠 수집·관측 기반 술래 행동·종료 판정·결과 저장·초기화를 연결한다. 제한 정보 제공, 관람 구성, 장애 정지와 배터리 기준 미달 시 시작 차단도 확인한다.

반복 시험으로 정상 완료율, 운영자 투입 시간, 회차 전환 시간과 충전·장애를 포함한 정상 제공 처리량을 측정하고, 추가 인력 지원을 기록하여 1명 운영 가정을 평가한다. 측정 결과를 가격·판매량·비용 시나리오에 반영해 운영 기여액과 필요한 판매량을 산정한다.

실제 구매·유료 재플레이와 대안 대비 선호는 후속 상업 검증으로 남긴다. 최종 시험 기준은 시험 전에 확정하며, 계산 완료와 경제 가설의 성립을 구분한다.

## 1.6 결론과 조건

기존 연구·제품 사례와 플랫폼 기능은 실물 로봇 체험의 MVP를 구성할 근거가 된다. 이번 프로젝트의 판단 대상은 **기본 체험의 구현·반복 운영 가능성과 조건별 경제성**이며, 시장 수요나 상용 수익성의 확정은 아니다.

추진에는 사용 가능한 로봇 2대와 충전 설비, 주행·조작·관람 공간, 확정된 규칙과 시험 기준이 필요하다. 1명 운영 가능성과 실제 처리량은 시험으로 확인한다. 필요한 판매량이 제공 가능한 수준을 초과하거나 추가 인력 지원이 필요하면 가격·구성·운영 모델을 재검토한다.

상용 추진 여부는 실제 구매 수요와 도입·운영 비용을 추가 확인한 뒤 판단한다. 이번 산정에서 제외한 수리·소모품·콘텐츠 제작·현장 지원·장비 교체 비용과 초기 투자 회수는 별도 분석한다.

#### ③ 상업적 판단

본 프로젝트는 현장에서 회차별로 제공하는 체험 콘텐츠에 해당한다. 상업적 기회는 실물 로봇 조작, 자율 술래와의 추격, 동행인의 관람을 결합하여 기존 화면 게임이나 사람이 직접 참여하는 체험과 다른 경험을 제공하는 데 있다.

현장 체험 시장과 다양한 운영 형식은 확인되지만, 설치형 로봇 게임의 직접 시장 규모, 국내 시설의 도입 의사, 고객의 결제 단가와 재구매 수요는 확인되지 않았다. 따라서 현재 자료는 차별화된 MVP를 구성하는 근거로 사용하며, 시장 진입의 타당성이나 수익성 확정으로 해석하지 않는다.

기반 기능의 존재만으로 두 로봇의 게임 통합이나 좁은 아레나의 정상 운영을 보장할 수는 없다. 또한 배터리 사양만으로 짧은 플레이 시간을 결정하거나 매 회차 충전을 요구하지 않는다. 플레이 시간은 경험·난이도·처리량에 따라 정하고, 충전은 전체 운영 용량에 반영한다.

## 2.3 As-Is / Baseline

비교 대상은 게임 규칙, 실물 조작 경험, 현장 체험 서비스 측면에서 선정한다. 각 대안은 일부 경험을 대체하지만, 동일한 상품이나 운영 조건을 가진 직접 경쟁 서비스로 단정하지 않는다.

## 3.2 Out of Scope

- Level 2·3, 추가 맵과 여러 캐릭터, 복합 미션 및 다종 아이템의 완성.
- 다수 플레이어의 동시 대전, 다수 아레나 운영, 외부 인터넷 원격 서비스의 상용 보장.
- 모든 사용자군의 접근성 보장, 실제 현장 체험 대비 우수성 또는 고객 수요 확정.
- 외부 결제 시스템·예약 시스템·상용 계정 시스템의 필수 구현. 유료 시험은 별도 확보 방식으로 수행 가능.
- 수리·소모품·콘텐츠 제작·현장 지원·장비 교체 비용의 이번 운영 기여액 산정. 이들 비용을 0원이라고 판단하지 않는다.
- 세부 게임 규칙의 본 초안 내 확정. 구현 시험 전 별도 규칙 기준판이 필요하다.

### 4.1.2 초기 지불·수익 구조

초기 분석에는 다음 구조를 적용한다.

> **플레이어 → 회차 이용료 → 서비스 운영 주체 → 인건비·공간비·기타 포함 운영비 지출**
> 

시스템 공급 거래가 추가될 경우에는 별도로 관리한다.

> **도입 구매자 → 장비 도입비 또는 사용료 → 시스템 공급자**
> 

회차 과금형 체험은 국내 방탈출 예약·결제 사례와 Activate의 입장권 기반 운영 모델에서 확인된다. 운영자와 콘텐츠 공급자 사이의 사용량 기반 거래는 Hero Zone의 라이선스 모델에서 확인된다.

이번 경제성 계산에는 플레이어 이용료를 운영 매출로 사용한다. 장비 판매·임대·콘텐츠 라이선스·수익 배분은 후속 공급 모델의 후보로 남긴다. 계약이 없는 상태에서 공급자의 예상 매출을 추가하지 않는다.

### 4.4.3 배터리를 반영한 운영 용량

**① 장기 반복 운영**

완전 운용과 완전 충전을 반복하는 단순 모델에서 배터리 가동 비율은 다음과 같다.

$$
A_b=\frac{\text{운용 시간}}{\text{운용 시간}+\text{충전 시간}} 
$$

| 계산 항목 | 운용 2.5시간 적용 | 운용 4시간 적용 |
| --- | --- | --- |
| 운용＋충전 주기 | 5시간 | 6.5시간 |
| 배터리 가동 비율 | 50.0% | 61.5% |
| 회차 6분 기준 충전 전 처리 속도 | 10회/시간 | 10회/시간 |
| 충전 포함 장기 평균 처리 용량 | **5.00회/영업시간** | **6.15회/영업시간** |

이는 장애·추가 복구가 없고, 제공 가능한 회차가 모두 판매된다는 예시다. 안내·초기화는 회차 6분 안에 포함되어 있어야 한다.

**② 완충 상태로 시작하는 일일 운영**

하루 운영은 시작 시 배터리가 충전되어 있으므로 장기 평균 가동 비율을 그대로 적용하지 않는다.

| 영업시간 | 운용 2.5시간 적용: 제공 시간 / 회차 수 | 운용 4시간 적용: 제공 시간 / 회차 수 |
| --- | --- | --- |
| **4시간** | 2.5시간 / 25회 | 4시간 / 40회 |
| **6시간** | 3.5시간 / 35회 | 4시간 / 40회 |
| **8시간** | 5시간 / 50회 | 5.5시간 / 55회 |

조건은 **완충 시작, 두 로봇 동시 충전, 회차 6분, 고객 수요 충분, 기타 손실 없음**이다. 종료 후 다음 영업일까지 완충할 수 있다고 가정한다.

따라서 **8시간 영업의 예시 용량은 50~55회, 시간당 평균 6.25~6.875회**다. 이는 판매 예측이나 실측값이 아니다.

### 4.4.4 매출·공헌이익 계산

| 기호 | 정의 |
| --- | --- |
| P | 회차당 매출액, 원/유료 회차 |
| V | 산정에 포함한 회차당 변동비 |
| W | 운영자 1명의 시간당 인건비 |
| F | 인건비 외 포함 고정 운영비, 원/영업시간 |
| H | 총 영업시간 |
| N | 해당 영업시간의 유료 판매 회차 |
| n | 영업시간당 유료 판매 회차, \(N/H\) |

| 지표 | 계산식 |
| --- | --- |
| **총 매출** | PN |
| **영업시간당 매출** | Pn |
| **회차당 공헌이익** | P-V |
| **총 운영 기여액** | (P-V)N-(W+F)H |
| **영업시간당 운영 기여액** | (P-V)n-W-F |
| **고정비 배부 후 회차당 기여액** | P-V-{W+F}/{n}, 단 n>0 |

상주 인건비는 시간 고정비로 처리한다. 회차당 공헌이익에서 인건비를 차감한 뒤 시간당 계산에서 다시 차감하지 않는다.

**8시간 영업·6분 회차·전 회차 판매 예시**에 적용하면 다음과 같다.

| 항목 | 운용 2.5시간 적용 | 운용 4시간 적용 |
| --- | --- | --- |
| 판매 회차 | 50회 | 55회 |
| 총 매출 | 50P | 55P |
| 시간당 매출 | 6.25P | 6.875P |
| 시간당 운영 기여액 | 6.25(P-V)-W-F | 6.875(P-V)-W-F |
| 회차당 기여액 — 고정비 배부 후 | P-V-0.16(W+F) | P-V-0.1455(W+F) |

실제 판매 점유율이 낮아지면 판매 회차와 매출은 감소하지만, 상주 인건비는 그대로 발생한다.

### 4.4.5 계산 결과의 적용 범위

현재 확정된 가격과 비용 금액이 없어 **원 단위 매출·이익은 확정하지 않는다.** 이번 계산은 공식 배터리 사양을 사용한 운영 용량과 수익 산식의 정리다.

사업성 판단에는 실제 회차 점유 시간, 영업시간, 판매 점유율, 가격·인건비·포함 비용을 입력해야 한다. 수리·콘텐츠 제작·장비 교체 등 제외 비용이 있으므로, 운영 기여액이 양수여도 최종 수익성이나 투자 회수가 확인된 것은 아니다.

담당자는 O-08에서 지정한다. 최초 시험은 기준선 확보에 사용하고, 보완 이후 최종 시험 결과와 구분한다. 20회·90%는 프로젝트 제안값이며 상용 신뢰성의 근거가 아니다. KPI-04는 정상 제공 실적이며 실제 판매량이나 확정된 최대 용량을 의미하지 않는다.

### 보조 지표

- **1명 운영:** 계획 외 추가 인력 지원 회차 수·지원 시간·지원 이유. 지원이 있으면 조건부 운영 결과로 표시한다.
- **제공 불가 시간:** 충전·장애·복구별 시간. 고객 부재 시간과 구분하고 회차 시간과 중복 차감하지 않는다.
- **장애와 접촉:** 원인별 중단 회차 수, 로봇 간·장애물·사람과의 의도하지 않은 접촉 건수. 접촉 제안 목표는 0건이며 게임상 포착은 접촉을 요구하지 않는다.
- **후속 관람 검증:** 관람 기준을 충족한 고유 관람객의 체류 시간·신청률·결제율. 신청과 결제, 관람과 대기를 구분한다.
- **후속 실물 가치 비교:** 비교 조건이 확보된 경우 전환율·재플레이율 차이를 측정한다. 비교 시험이 없으면 상대적 우수성은 미검증으로 남긴다.

KPI-07의 계산 완료와 경제 가설의 성립은 별도로 판단한다. 기여액이 양수여도 제외 비용을 반영한 최종 수익성과 투자 회수를 입증하지 않는다.

BA-04의 측정 완료만으로 1명 운영이 검증된 것은 아니다. BA-06은 음수 결과도 유효한 산출물이며, 양수 시나리오도 실제 판매 수요를 입증하지 않는다. 미확정 기준의 항목은 합격으로 처리하지 않고 측정 완료 또는 판정 보류로 기록한다.

## 10.1 공통 시험 조건

- 장비·센서·소프트웨어·모델·맵·규칙·UI 버전을 기록하고 시험 묶음 내 고정한다.
- 시작 위치·배터리·장애물·조명·오브제·네트워크·사용자 시야를 기록한다.
- 시작한 모든 회차와 정상 종료·장애·계획 외 지원을 기록한다. 실패를 분모에서 제거하지 않는다.
- 업무 투입 시간과 경과 시간을 구분하고, 로그 시각은 동일한 시간 기준으로 기록한다.
- 기준선·최종 시험, 무료·유료·용량 시험을 구분한다. 최종 시험 목표는 결과 확인 전에 확정한다.

## 10.2 미달성 처리

실패 원인과 영향 요구사항을 기록하고 보완 후 관련 시나리오를 재시험한다. 변경 버전·조건의 결과를 임의 합산하지 않는다. 조건부 수용에는 제외 기능·사용 조건·미달 KPI를 명시한다. 고객 수요와 경제 가설 미검증을 기술 성공으로 대체하지 않는다. 범위 변경과 인수 판정은 O-08의 승인자가 확인한다.

# 11. Example Use Cases

## Case1 — 기본 게임 체험

- **사용자·목적:** 플레이어가 조작석에서 생존자를 조작해 열쇠 수집·탈출을 시도한다.
- **시작 조건:** 두 로봇·아레나·배터리 준비, 안내 완료, 규칙 기준판 적용.
- **정상 흐름:** 조작·목표 안내 → 회차 시작 → 제한 정보 확인·조작 → 획득·술래 행동 → 규칙에 따른 종료 → 결과 표시·저장.
- **예외 흐름:** 단절·장애 시 정지·중단 사유 보존. 게임상 패배는 정상 결과로 기록.
- **완료 결과:** 회차 ID·진행 상태·종료 사유·버전 기록.
- **관련 요구사항:** BR-0104·06·0913·18, BA-01·02.

## Case2 — 종료 후 다음 회차 준비

- **사용자·목적:** 운영자가 다음 고객을 위한 회차를 준비한다.
- **시작 조건:** 회차 종료 또는 중단.
- **정상 흐름:** 결과 확인 → 초기화 → 로봇·게임 상태 확인 → 배터리 점검 → 준비 완료 기록 → 다음 고객 안내.
- **예외 흐름:** 복귀 실패·배터리 부족 시 시작 차단, 복구·충전·지원 시간 기록.
- **완료 결과:** 준비 상태·전환 시간·업무 시간·지연 사유.
- **관련 요구사항:** BR-05·06·10·15~17, BA-03·04.

## Case3 — 장애 중단과 복구

- **사용자·목적:** 운영자가 통제 불가·장애 상태의 회차와 로봇을 중단한다.
- **시작 조건:** 통신 단절·동작 이상·운영자 정지 요청.
- **정상 흐름:** 정지 → 중단 표시·원인 보존 → 운영자 확인·복구 → 초기화 → 새 회차 준비.
- **예외 흐름:** 복구 불가 시 제공 불가 상태 유지. 개발자 지원은 계획 외 개입으로 기록.
- **완료 결과:** 중단 회차·장애 유형·정지·복구·지원 시간.
- **관련 요구사항:** BR-05·06·10·13~17, BA-03·04.

## Case4 — 실물 추격 관람

- **사용자·목적:** 관람객이 역할·목표 안내를 보고 실제 추격을 관람한다.
- **시작 조건:** 관람 위치·표시·안내·플레이어 시야 조건 확정.
- **정상 흐름:** 안내 확인 → 생존자·술래 구분 → 실제 추격 관람 → 종료 상태 확인.
- **예외 흐름:** 시야 가림이나 제한 정보 전달이 발생하면 배치·관람 조건 조정.
- **완료 결과:** 관람 구성 점검 기록. 관람 만족도·구매 전환은 별도 후속 검증.
- **관련 요구사항:** BR-07·12, BA-02.

## 후속 상업 검증 시나리오

관람 기준을 충족한 고객에게 동일 가격·내용을 안내하고 신청·결제를 구분하여 기록한다. 유료 재플레이는 동일 관찰 기간과 익명 고객 ID로 측정한다. 비교 시험이 없으면 구매·재플레이를 로봇 효과의 단독 증거로 해석하지 않는다. 관련 지표는 BR-KPI-05·06 및 관람 보조 지표이며 이번 MVP 필수 흐름에는 포함하지 않는다.

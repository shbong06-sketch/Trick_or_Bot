## 검증 목적과 현재 기록

Nav2의 단일 목표 이동, 여러 pose를 통과하는 이동, 순차 waypoint 방문, 경로 생성 기능을 비교하고, AMCL에서 출력한 로봇 위치를 확인한다.

현재 페이지에는 **기능별 시연 영상 4개와 AMCL pose 원본 로그 1개**가 있다. 실행 코드, 목표 좌표 목록, 설정 파일, action 최종 결과는 첨부되어 있지 않다. 따라서 아래에서는 공식 기능 설명과 이번 실험의 관찰을 구분한다.

## 1. Nav2 기능 비교

원문의 nav_to_pose / nav_through_pose / follow_waypoints / create_path는 실험 구분명이다. 아래 API는 공식 Simple Commander의 대응 기능이며, 실제 시험 코드에서 호출한 함수는 별도 확인이 필요하다.

| 실험 구분 | 공식 API / Action | 목적 | 구분할 점 |
| --- | --- | --- | --- |
| nav_to_pose | goToPose() / NavigateToPose | 하나의 목표 pose로 이동 | 최종 위치와 방향을 목표로 설정 |
| nav_through_pose | goThroughPoses() / NavigateThroughPoses | 여러 pose를 통과하는 이동 | 각 지점에서 별도 작업·정지를 수행하는 방식과 구분 |
| follow_waypoints | followWaypoints() / FollowWaypoints | waypoint를 순서대로 방문 | 각 지점에서 TaskExecutor로 대기·촬영 등 작업 가능 |
| create_path | getPath() 또는 getPathThroughPoses() | 시작점과 목표를 연결하는 경로 계산 | 경로 생성과 실제 주행은 구분; 시험의 정확한 API는 미기록 |

### NavigateThroughPoses와 FollowWaypoints의 차이

NavigateThroughPoses도 여러 pose를 통과하도록 요청하는 기능이다. 중간 pose를 “방문하지 않는 단순 참고점”으로만 설명하면 부정확하다. 각 점에서 정지·작업하는 방식과 구분하되, 통과 판정과 움직임은 사용한 BT와 planner/controller 설정에 따라 확인해야 한다.

FollowWaypoints는 각 waypoint에 대해 NavigateToPose를 순서대로 요청하고, 도착 후 설정된 TaskExecutor를 실행한다. 실패 시 전체 중단 또는 다음 지점 진행은 stop_on_failure 설정에 따라 달라진다. 도착은 허용오차에 따른 판정이므로 좌표를 수학적으로 정확히 찍는다는 뜻은 아니다.

### 시작점과 최종 목표가 같은 시험

원문에는 “시작과 도착점이 같으면 nav_through_pose가 움직이지 않고 바로 도착 판정”이라는 관찰이 있다. **이번 시험에서 관찰한 현상으로 보존하되, 모든 NavigateThroughPoses의 일반 규칙으로 확정하지 않는다.**

재현 시 실제 전송된 pose 목록, 중간 pose 포함 여부·순서, 사용한 BT, 최종 목표 허용오차, action 결과를 기록한다. 중간 지점 방문이 필수인 복귀 순찰 시나리오라면 FollowWaypoints도 함께 비교한다.

- 기존 비교 메모 — 원문 보존
    - Nav_through_pose와 follow waypoints 차이
        - Nav_through_poses : 여러 포인트를 관찰하고, target point로 이동하는 것이 목표 — 중간 point를 guide를 삼아서 path planning이 이루어짐
            - 다만, 중간 경유점을 찍고 이동하지는 않는다.
        - follow waypoints : 매 경우점을 찍고 이동, 중간 경유점을 지나며 가는 것이 목표
        - 만약 시작과 도착점이 같은 경우,
            - nav_through_pose는 움직이지 않고 도착 판정을 바로 하게 된다.

## 3. AMCL 기반 로봇 위치 확인

### 확인 명령

```bash
ros2 topic echo /robot1/amcl_pose --once
```

AMCL 메시지에는 map 기준의 로봇 위치와 orientation, 추정 공분산이 기록되어 있다. 아래는 원본 메시지 한 건에서 추출·계산한 값이다.

| 항목 | 값 | 해석 |
| --- | --- | --- |
| frame_id | map | map 좌표계의 위치 추정 |
| 위치 (x, y, z) | (−1.3160, −1.1451, 0.0000) m | 실제 위치의 참값이 아닌 추정값 |
| Quaternion (x, y, z, w) | (0, 0, 0.25196, 0.96774) | 메시지에 기록된 방향 |
| Yaw | 약 0.5094 rad / 29.19° | 평면 quaternion에서 계산 |
| x 분산 | 0.047064 m² | covariance 인덱스 0 |
| y 분산 | 0.023961 m² | covariance 인덱스 7 |
| yaw 분산 | 0.063900 rad² | covariance 인덱스 35 |
| 추정 표준편차 (x, y, yaw) | 약 0.217 m / 0.155 m / 14.48° | 위 분산의 제곱근; 실제 측정 오차와 구분 |

공분산은 위치 추정의 불확실성을 나타낸다. 실제로 로봇이 21.7 cm 또는 15.5 cm 틀렸다는 뜻은 아니다. 또한 한 메시지만으로 AMCL 수렴이나 주행 중 안정성을 판단하기는 어렵다.

## 4. 프로젝트 적용 방향

| 사용 상황 | 검토할 기능 | 선택 이유 |
| --- | --- | --- |
| 객체의 접근 목표로 이동 | NavigateToPose | 변환된 객체 좌표에서 정지 거리를 반영한 단일 goal |
| 여러 구간을 연속해서 이동 | NavigateThroughPoses | 중간 pose를 포함한 이동 요청 |
| 조사·촬영 지점을 방문 | FollowWaypoints | 각 지점 방문과 작업 실행 |
| 주행 전 경로 확인 | 경로 생성 API | 계획된 경로를 확인한 뒤 별도로 주행 여부 결정 |

객체의 map 좌표 변환과 주행 목표 구성은 관련 기술검증 페이지에서 함께 확인한다.

## 5. 다음 검증 항목

- 기능별 실행 코드·호출 API·설정 파일과 goal의 frame_id 및 전체 좌표 목록을 기록한다.
- 동일한 시작 조건에서 목표 도착 여부, 경유점 방문 여부, 이동 시간과 최종 위치 오차를 비교한다.
- 완료 상태와 성공을 구분해 최종 action 결과를 남긴다. 실패·취소도 기록한다.
- 시작점과 최종 목표가 같은 시나리오를 재현하고, 중간 지점이 실제로 요청·통과되는지 확인한다.
- AMCL은 초기 위치 설정 후 반복 메시지와 실제 기준 위치를 비교해 추정 안정성과 위치 오차를 따로 평가한다.

**현재 확보한 자료는 Nav2 기능별 시연 기록과 AMCL pose 출력이다.** 기능 선택 근거는 정리했으며, 성공률과 도착 정확도는 추가 시험 결과로 보완한다.

### DETR

객체 탐지 모델은 이미지에서 ‘분류 결과’와 해당 객체 ‘bbox 위치’를 반환한다.

DETR은 이를 정해진 개수의 객체 후보를 만들어 정답 객체와 대응시키는 문제로 다룬다.

| 구성 요소 | 역할 | RC car 이미지에서의 의미 |
| --- | --- | --- |
| Backbone | 이미지에서 시각적 특징 추출 | 바퀴·윤곽·색·질감 등의 단서 추출 |
| Encoder | 특징 간 관계 처리 | 주변 물체와 배경을 함께 고려 |
| Object query | 물체 후보를 표현하는 벡터 | “탐지 후보 한 개”를 담는 내부 표현 |
| Decoder | 후보가 이미지 특징을 참조하며 예측 개선 | 후보의 클래스와 bbox를 구체화 |
| Prediction head | 최종 클래스 점수와 bbox 출력 | car, confidence, 좌표 출력 |

Object query는 이미지 한 프레임에서 물체 후보를 표현하는 내부 벡터이다. 고정된 bbox나 시간에 따라 유지되는 tracking ID가 아니며, 영상 추종에는 별도의 tracker가 필요하다.

학습 시에는 Hungarian matching으로 예측 후보와 GT를 일대일 대응시킨다. 분류 비용과 bbox 위치 비용 등을 합산한 전체 대응 비용이 최소가 되도록 배정한다. 정답별로 독립적으로 가장 가까운 예측을 고르는 방식과는 다르다.

매칭된 예측에는 클래스와 위치 손실을 적용하고, 매칭되지 않은 예측에는 정답 객체를 나타내지 않도록 분류 손실을 적용한다. 원본 DETR의 no-object 클래스와 후속 모델의 sigmoid 기반 분류는 구현 방식이 다를 수 있다.

이 방식은 객체마다 하나의 예측을 내도록 학습하므로, 기본 DETR 계열은 중복 bbox 제거를 위한 NMS 없이 탐지하도록 설계되어 있다. 다만 confidence 필터링과 좌표 변환 등 후처리는 여전히 필요하고, 중복·오탐이 완전히 사라지는 것은 아니다.

**추가 개념: Attention과 bbox 학습**

- Self-attention은 같은 특징 집합 안에서 관련 정보를 참조한다. Cross-attention은 query가 이미지 특징을 참조해 객체 정보를 가져오는 과정이다.
- Backbone의 특징은 사람이 정의한 바퀴·윤곽 목록이 아니라 학습된 수치 표현이다. 표의 RC car 예시는 이해를 돕는 설명이다.
- bbox 회귀는 연속적인 위치를 예측하는 작업이다. L1 손실은 좌표 차이를, GIoU 등의 손실은 두 bbox의 공간적 일치 정도를 평가한다.
- 학습용 Hungarian matching과 Test에서 TP·FP·FN을 계산하는 평가용 매칭은 별개다. 평가에서는 모든 모델에 동일 클래스·IoU 기준을 적용한다.

### RT-DETR : Transformer의 연산을 효율적으로 구성

**대상: 원본 RT-DETR-L / Ultralytics 구현. RT-DETRv2·v4와 구분한다.**

**해결하려는 문제**

고해상도 다중 스케일 특징을 모두 attention으로 처리하면 연산량이 커진다. RT-DETR은 특징 관계 처리와 스케일 결합을 분리해 실시간 탐지를 목표로 한다.

**처리 구조**

이미지 → CNN backbone → 여러 해상도의 특징 → Efficient Hybrid Encoder → 초기 query 선택 → Transformer decoder → 클래스·bbox.

**핵심 원리**

1. **AIFI: Attention-based Intra-scale Feature Interaction.** 의미 정보가 풍부하고 공간 크기가 작은 고수준 특징에서 self-attention을 수행한다. 모든 해상도에 무거운 attention을 반복하는 비용을 줄인다.
2. **CCFM: CNN-based Cross-scale Feature Fusion.** 서로 다른 해상도의 특징을 CNN 기반 경로로 결합한다. 세부 위치 정보와 고수준 의미 정보를 함께 활용한다.
3. **Uncertainty-minimal query selection.** 분류와 위치 품질 사이의 불일치를 줄이도록 학습해 decoder에 좋은 초기 후보를 제공한다. IoU-aware query selection으로도 설명되며, 정답 IoU를 추론 시 직접 사용하는 것은 아니다.
4. **Decoder의 단계별 개선.** 후보가 특징을 참조하며 클래스와 bbox를 반복적으로 수정한다. decoder 깊이를 줄이는 속도 조정은 성능 검증을 동반해야 한다.

**실험 해석**

RT-DETR-L은 N 크기 후보보다 큰 모델이다. 동일 크기 구조 비교가 아니라 운영 후보 비교로 기록한다. 가림에 더 강할 것이라는 기대는 가설이며 거리별 Recall·처리 시간으로 확인한다.

[근거: RT-DETR 논문·프로젝트](https://zhao-yian.github.io/RTDETR/) / [Ultralytics 구현 문서](https://docs.ultralytics.com/models/rtdetr)

### RF-DETR Nano : 사전학습 특징과 정확도·지연 균형

**대상: 공개 RF-DETR Nano detection 모델. DINO detector·Grounding DINO와 구분한다.**

**해결하려는 문제**

사전학습 표현을 활용하면서 목표 데이터와 하드웨어에 맞는 정확도·지연 균형을 찾는다.

**처리 구조**

이미지 패치 → DINOv2 기반 ViT backbone → multi-scale projector → deformable Transformer decoder → 클래스·bbox.

**핵심 원리**

1. **DINOv2 사전학습.** 대규모 이미지에서 학습한 특징을 탐지에 활용한다. 이번 fine-tuning에서는 탐지 데이터로 모델을 적응시키며, DINOv2 사전학습을 처음부터 재실행하지 않는다.
2. **효율적인 attention.** Window 기반 attention 등으로 backbone 계산을 관리한다. Deformable attention은 query에 관련된 일부 샘플 위치의 특징을 참조한다. 모든 이미지 위치를 동일하게 처리하지 않는다.
3. **특징 변환.** ViT 특징을 decoder가 활용할 수 있는 여러 스케일의 표현으로 변환한다. RT-DETR의 CNN 기반 encoder와 같은 구조라고 해석하면 안 된다.
4. **Weight-sharing NAS.** 가중치를 공유하는 구성에서 입력 해상도·patch 크기·query 수·decoder 깊이 등의 조합을 탐색한다. 정확도와 지연의 Pareto 균형을 찾는다. 공개 Nano fine-tuning은 고정된 제공 구조를 학습하는 것이며 NAS를 자동으로 새로 수행하는 것이 아니다.

**실험 해석**

Nano 기본 입력 384에서 원거리 작은 객체의 정보가 충분한지 확인한다. 적은 데이터에서 사전학습 특징이 도움이 되는지는 결과로 검증한다. 파라미터 수만으로 다른 모델보다 빠르다고 판단하지 않는다.

[근거: RF-DETR 논문](https://arxiv.org/abs/2511.09554) / [공식 구조 설명](https://huggingface.co/Roboflow/rf-detr-small) / [공식 코드](https://github.com/roboflow/rf-detr)

### D-FINE-N : bbox 위치를 확률분포로 정교하게 개선

**대상: 공식 D-FINE-N. 개선의 중심은 bbox 회귀다.**

**해결하려는 문제**

경계를 좌표로만 표현하는 대신 위치 분포를 단계별로 정교하게 개선해 공간 정합성을 높인다.

**처리 구조**

CNN backbone → 다중 스케일 특징 처리 → decoder → 경계 위치 분포의 반복 개선 → 클래스·최종 bbox.

**핵심 원리**

1. **FDR: Fine-grained Distribution Refinement.** bbox 경계의 상대 위치를 이산 확률분포로 표현하고 decoder 단계에서 잔차를 통해 개선한다. 분포를 좌표로 변환해 최종 bbox를 얻는다. 분포는 탐지 confidence와 별개의 위치 표현이다.
2. **GO-LSD: Global Optimal Localization Self-Distillation.** 더 정교해진 위치 분포의 정보를 얕은 단계에 전달해 위치 학습을 돕는다. 같은 모델 안의 자기 증류이며, 운영 시 별도 teacher 모델을 추가 실행하는 방식이 아니다.

**직관적인 예**

경계 후보의 상대 거리 8·10·12에 확률 0.1·0.7·0.2가 있으면 가중 평균은 10.2이다. 이는 분포에서 위치를 얻는 원리를 설명하는 가상 예이며 실제 bin·좌표 변환 설정을 그대로 나타내지는 않는다.

**실험 해석**

엄격한 IoU에서도 bbox가 맞는지 보는 mAP50-95를 우선 확인한다. car bbox 중심은 좌표 계산에 활용되므로 연속 프레임의 흔들림도 측정한다. 다만 FDR은 시간적 tracking 기능이 아니며 bbox 중심이 물체의 실제 3D 중심이라는 보장은 없다.

[근거: D-FINE 논문](https://arxiv.org/abs/2410.13842) / [공식 코드·설정](https://github.com/Peterande/D-FINE)

### DEIM : 매칭 수와 품질을 개선하는 학습 프레임워크

**대상: DEIM v1 + D-FINE-N, 설정 deim_hgnetv2_n_coco.yml. DEIMv2의 DINOv3 기반 모델과 구분한다.**

**해결하려는 문제**

일대일 매칭은 정답 하나당 긍정 예측 하나를 배정하므로 학습 신호가 적다. 특히 초기의 부정확한 매칭을 충분히 개선하지 못하면 수렴이 느려진다.

**핵심 원리**

1. **Dense O2O.** Mosaic·MixUp 등의 증강으로 한 이미지 안의 정답 객체 수를 늘린다. 객체 2개면 긍정 매칭 2개, 결합 이미지에 객체 8개면 긍정 매칭 8개가 되는 식이다. 한 정답에 여러 예측을 붙이는 O2M으로 바꾸는 것은 아니다.
2. **MAL: Matchability-Aware Loss.** 매칭된 bbox의 IoU와 분류 confidence를 고려해 손실을 구성한다. 기존 손실에서 학습 신호가 약해질 수 있는 낮은 품질의 긍정 매칭도 효과적으로 최적화한다. 낮은 품질 매칭을 전부 버리는 방식과 다르다.
3. **학습과 추론의 구분.** Dense O2O 증강과 MAL은 학습 개선이다. 추론에서는 학습된 D-FINE 탐지 구조를 실행하므로 개선 목표는 추가 추론 비용보다 수렴 속도와 최종 성능에 있다.

**실험 해석**

D-FINE-N과 같은 epoch의 Val 성능, 목표 성능 도달 시간, 최종 mAP를 비교한다. 학습 epoch가 줄었다고 실행 추론 시간이 줄었다고 해석하지 않는다. 공개 가중치를 각각 사용하는 비교에는 사전학습 차이가 포함되므로 DEIM만의 인과 효과를 분리한 ablation으로 주장하지 않는다.

[근거: DEIM 논문](https://arxiv.org/abs/2412.04234) / [공식 코드](https://github.com/Intellindust-AI-Lab/DEIM)

### 모델별 개선 지점과 확인할 결과

| 모델 | 개선 지점 | 우리 실험의 확인 항목 |
| --- | --- | --- |
| RT-DETR-L | encoder 연산과 초기 query | 정확도 이득 대비 노드 평균·P95 지연 |
| RF-DETR Nano | 사전학습 표현과 구조 균형 | 384 입력의 원거리 Recall·일반화 |
| D-FINE-N | bbox 위치 분포 개선 | mAP50-95·bbox 정합성·중심 흔들림 |
| DEIM-D-FINE-N | 긍정 매칭 수·손실 개선 | 수렴 epoch·학습 시간·최종 성능 |

**검수 결론**

기존 DETR 요약은 개념적으로 적절하다. 전체 비용을 최소화하는 Hungarian matching, 구현별 no-object 처리 차이, query와 tracking ID의 구분을 보강했다. 네 후보의 공통 출력은 클래스·confidence·bbox이며 target_id 유지는 별도 tracker가 담당한다.

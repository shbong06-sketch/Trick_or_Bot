## 1. 한 줄 요약

3 m × 3 m 아레나에서 TurtleBot4 두 대가 벌이는 **할로윈 술래잡기 체험 게임**이다.
플레이어는 웹 화면(WASD + 1인칭 영상)으로 **도망자 로봇**을 조작해 열쇠를 모으고 탈출한다.
**술래 로봇**은 카메라로 도망자(호박 머리 오브제)를 직접 인식하고 순찰 → 의심 → 추적 → 체포·수색 → 복귀를 스스로 판단한다.
과학관 같은 체험 시설이 **외부 패키지**(로봇 2대 + 아레나 + 관제 PC)로 도입해 운영하는 상품을 가정한다.

## 2. 문제 정의 (발표문서 인용)

| # | 문제 | 팀 Notion이 든 근거 |
|---|---|---|
| P-1 | 대중은 로봇을 많이 봤지만 **스스로 보고 판단하는 로봇(피지컬 AI)을 직접 상대해 본 적이 거의 없다.** 뉴스는 피지컬 AI로 가득하고 정부는 2030년까지 20만 대 보급을 말하는데, 서빙 로봇과의 차이를 체감할 곳이 없다 | 한국 산업용 로봇 밀도 세계 1위(1만 명당 1,220대), 한국리서치(2026.6) AI·로봇 도입 긍정 84%와 일자리 불안 83%가 함께 나타남 |
| P-2 | 짧은 핸즈온 체험만으로도 로봇에 대한 편안함·수용성이 오르지만 그런 체험의 자리가 부족하다 | Spot 팝업 부스 전후 설문(N=753)에서 편안함 증가, 노인 대상 시연 전후 유용성 인식 증가 |
| P-3 | 국내 체험은 **아동·청소년 교육에 집중**돼 있고, 14세 이상 일반 성인이 로봇을 직접 조작하는 체험은 공백이다. 있는 체험은 조종·관람·코딩 수준에 머문다 | 서울RAIM 해설 회차당 15명·100% 예약제, 국립과천과학관 로봇테마관은 관람 중심 |
| P-4 | 기관(과학관 등)은 장비·강사 역량이 없어 외부 패키지 없이는 운영하기 어렵다 | 상업 환경 분석 요약 3 |

## 3. 대상과 구매자

| 구분 | 대상 | 제외 | 이유 |
|---|---|---|---|
| 사용자 | 로봇·AI에 관심이 생긴 일반인 전 연령(초등 고학년~성인), 과학관 방문 가족·개인·청년 | 로봇 업계 관계자·전공자 | 문제는 "일반인이 피지컬 AI를 겪어 본 적 없음" |
| 구매자 | 국공립·사립 과학관 | 학교(정규 수업) | 학교는 예산 0원이 25%, 교사 역량 부족(서울교육청 2025) |
| 2차 구매자 | 지자체 로봇 축제, 박람회 | 게임쇼, 상업 아케이드 | 같은 장비로 단기 대여 가능 |

## 4. 왜 게임인가 (예상 질문 대비)

- 게임 규칙은 복잡한 로봇 제어를 즉각적인 피드백으로 바꿔 몰입도를 높인다(발표문서 인용: 효과 크기 0.65, Radhiani 2026).
- 센서 데이터(라이다, 카메라)를 미니맵·장애물 표시·게이지 같은 **게임 UI로 바꿔** 비전문가도 로봇의 인지·판단 과정을 읽게 한다.
- 가상 화면만이 아니라 **실물 반응**이 따를 때 통제감과 현실 몰입이 커진다.

## 6. 비즈니스 요구사항 (발표문서 BR-01~10, 참고용)

> **SRD v0.2의 추적 기준은 BRD-N의 BR-01~18(BRD 6장), BR-KPI-01~07, BA-01~06이다.** 아래 표는 발표문서 번호이며 SRD에서는 부록 B의 TR 대응으로만 쓴다. → OI-02

> ID는 **발표문서 기준**이다. BRD-N의 BR-01~18과 번호가 겹쳐 내용이 다르므로 SRD·SDD에서 BRD-N을 인용할 때는 `BRD-N BR-xx`로 구분한다. → OI-02

| ID | 요구사항 | 근거 | 검증 방법(발표문서) |
|---|---|---|---|
| BR-01 | 14세 이상 일반인이 **사전 교육 없이** 실물 로봇을 직접 조작하는 게임 체험을 제공한다 | 성인 대상 조작 체험 공백 | 첫 방문자가 설명 없이 플레이를 시작, 플레이 후 조작 난이도 설문 |
| BR-02 | 로봇이 **스스로 보고·판단하고·쫓는 과정**을 참여자가 겪는다 | 기존 체험은 조종·관람·코딩에 그침 | 술래의 자율 상태 전환이 사람 개입 없이 동작(Case1) |
| BR-03 | 동행인·대기 인원이 **관람만으로 로봇의 판단 과정을 볼 수 있다** | 게임 UI로 ROS 시각화 | 관람 화면에 술래 상태·게이지·인식 결과 표시, 관람자 이해도 설문 |
| BR-04 | 게임 규칙이 **반복 플레이와 재도전**을 유도한다 | 재방문 | 레벨 3종, 리더보드, 재도전 의향 설문 |
| BR-05 | 운영자 **1명이 한 회차를 처음부터 끝까지** 운영한다 | 기관은 장비·강사 역량 없음 | 회차당 운영자 인시·개입 횟수(Case2) |
| BR-06 | 회차 종료 후 **짧은 시간 안에 다음 손님**을 받는다 | 소형 공간 처리량 | 전환 시간, 시간당 회차 수(Case2) |
| BR-07 | 장애·통신 단절 시 **스스로 안전하게 멈추고 복구 가능**하며 사람·로봇 충돌이 없다 | 공공·상업 시설 설치 전제 | 충돌 0회, 정지·복구 시간 기록(Case3) |
| BR-08 | 레벨·테마·지도를 **소프트웨어와 소품 교체**로 바꾼다 | 시즌·장소별 재사용 | 교체 인시 측정 |
| BR-09 | 모든 회차의 **결과·운영 지표가 자동으로 남는다** | 기관 성과 보고, 사업성 추정 | 로그 필수 필드 누락 0건 |
| BR-10 | 외부 패키지(로봇 2대 + 아레나 + 관제 PC)로 기관에 **설치·운영**할 수 있다 | 수요처 = 박람회·과학관·교육기관 | 설치 1일, 운영자 교육 1시간(가정) → 대응 요구 없음, OI-16 |

우선순위 열은 발표문서에서 비어 있다. 팀이 정한다.

## 7. 비즈니스 가치 측정 (BRD-N 5장 인용)

MVP에서는 정상 회차 제공과 반복 운영 가능성을 측정하고 경제성 시나리오에 반영한다.

| KPI | 지표 | 제안 목표 |
|---|---|---|
| BR-KPI-01 | 정상 회차 완료율 | 최종 시험 20회 중 18회 이상 |
| BR-KPI-02 | 회차당 운영자 투입 시간 | 기준선 측정 후 시험 전 확정 |
| BR-KPI-03 | 회차 전환 시간(중앙값·90백분위) | 시험 전 확정. 발표문서 TR-10은 종료부터 다음 회차 준비까지 ≤90 s |
| BR-KPI-04 | 정상 제공 처리량(회/시간) | 경제성 시나리오의 필요 판매량과 비교 |
| BR-KPI-05~06 | 유료 전환율·재플레이율 | 후속 상업 검증, MVP 합격 판정 제외 |
| BR-KPI-07 | 영업시간당 운영 기여액 (P−V)n−W−F | 0원/시간 이상이면 가설 성립 |

시작한 모든 회차를 분모에 넣고, 장애 중단과 계획 외 개발자 개입 회차는 정상 완료에서 뺀다.

## 8. 유즈케이스 (발표문서 Case1~3)

| Case | 사용자·목적 | 정상 흐름 | 예외 흐름 |
|---|---|---|---|
| 1. 기본 게임 체험 | 플레이어가 조작석에서 도망자를 조작해 열쇠 수집·탈출 | 조작·목표 안내 → 회차 시작 → 제한 정보 확인·조작 → 획득·술래 행동 → 규칙에 따른 종료 → 결과 표시·저장 | 단절·장애 시 정지·중단 사유 보존. 게임상 패배는 정상 결과로 기록 |
| 2. 종료 후 다음 회차 준비 | 운영자가 다음 고객 회차를 준비 | 결과 확인 → 초기화 → 로봇·게임 상태 확인 → 배터리 점검 → 준비 완료 기록 → 다음 고객 안내 | 복귀 실패·배터리 부족 시 시작 차단, 복구·충전·지원 시간 기록 |
| 3. 장애 중단과 복구 | 운영자가 통제 불가·장애 상태의 회차와 로봇을 중단 | 정지 → 중단 표시·원인 보존 → 운영자 확인·복구 → 초기화 → 새 회차 준비 | 복구 불가 시 제공 불가 상태 유지. 개발자 지원은 계획 외 개입으로 기록 |

## 9. 가정·의존성·위험 요약 (BRD-N 9장 인용)

- 가정: 9 m²에 2대의 회피·목표 이동 공간을 구성할 수 있다(A-02), 상주 운영자 1명이 반복 운영을 처리한다(A-03), 공식 배터리 범위(2.5~4시간)를 초기 입력으로 쓴다(A-04).
- 의존성: 로봇 2대·충전 설비(D-01), 아레나·조작·관람 공간(D-02), 네트워크·관제 장비(D-03).
- 위험: 조명·가림으로 탐지 불안정(RISK-01), 좁은 아레나의 접촉·교착(RISK-02), 직접 관찰로 제한 정보가 무력화(RISK-03), 조작 지연·연결 상실(RISK-04), 충전·복구로 처리량 저하(RISK-05).

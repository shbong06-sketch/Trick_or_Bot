# Trick or Bot — Level 1 ROS 2 인터페이스 정의서

**기준일:** 2026-10-10  
**환경:** ROS 2 Jazzy / TurtleBot4 2대  
**인터페이스 패키지:** `tob_interfaces`  
**적용 범위:** Level 1

---

## 1. 목적과 설계 원칙

본 문서는 Trick or Bot Level 1에서 사용하는 ROS 2 인터페이스의 역할, 발행자, 구독자, 담당 영역 및 데이터 처리 규칙을 정의한다.

팀원들이 각자의 노드를 독립적으로 개발하더라도 동일한 메시지 형식과 통신 규칙으로 연결할 수 있도록 하는 것이 목적이다.

### 기본 원칙

- 기존 `tob_interfaces` 메시지 및 서비스 6개를 사용한다.
- 기능별 노드는 자신의 역할에 필요한 데이터만 발행하고 사용한다.
- 게임 규칙의 최종 판정은 `game_manager_node.py`가 담당한다.
- 웹은 ROS에서 결정한 게임 상태를 표시하고 조작 요청을 전달한다.
- 감지 노드는 목표를 인식하고, 위치 계산 노드는 지도 좌표를 계산하며, 제어 노드는 행동을 결정한다.
- 유효하지 않은 위치나 오래된 감지를 새로운 데이터처럼 사용하지 않는다.
- 로봇의 이동 안전은 게임 로직과 독립적으로 관리한다.
- 하드코딩을 최소화하고 환경별 설정은 YAML 파일에서 관리한다.

**중요:** 이 문서는 통신 계약을 정의한다. 각 메시지 필드의 최종 이름과 타입은 실제 `.msg`, `.srv` 파일을 기준으로 한다. 본 문서와 실제 인터페이스가 다를 경우 팀 간 확인 후 함께 수정한다.

## 2. Level 1 구현 범위

### 2.1 구현하는 기능

**Pumpkin (플레이어 로봇)**

- 사용자의 키보드 조작으로 이동한다.
- 사탕을 획득하고 탈출존으로 이동한다.
- 지도상 위치를 게임 관리 노드와 웹에 제공한다.
- 안전 조건을 위반하면 이동이 차단된다.

**Boo (추격 로봇)**

- Nav2를 사용해 지정된 순찰 지점을 이동한다.
- 카메라로 Pumpkin을 감지한다.
- 감지 결과와 유효한 지도 위치에 따라 추격한다.
- 감지를 잃으면 Boo FSM의 규칙에 따라 탐색 또는 순찰 상태로 전환한다.
- 안전 조건을 위반하면 이동이 차단된다.

**게임 관리**

- 사탕 획득 판정
- Boo에게 잡힘 및 하트 감소 판정
- 게임 타이머 관리
- 탈출 가능 조건 판정
- 레벨 성공 및 실패 판정
- 현재 게임 상태와 이벤트 발행

**웹 화면**

- 두 로봇의 현재 위치 표시
- 게임 상태 및 남은 시간 표시
- 사탕 획득 상태 및 하트 표시
- Boo의 행동 상태 표시
- 게임 시작, 일시정지, 재개, 초기화 요청
- 게임 결과 및 이벤트 연출

### 2.2 Level 1에서 구현하지 않는 기능

- 외부 웹캠을 이용한 추가 위치 추정
- 깊이 카메라 기반 3D 위치 계산
- 게임 종료 후 로봇 자동 복귀
- 별도 탈출문 개방 및 대기 로직
- 과거 전체 이벤트 재생 시스템
- 복잡한 다중 목표 추적 시스템

위 기능은 Level 1의 필수 범위에서 제외하며, 기존 구현만으로 필요한 게임 동작이 가능하도록 구성한다.

## 3. 담당자 및 파일별 역할

파일명은 지금까지 논의한 패키지 구조 기준의 예상 이름이다. 실제 구현 파일명이 다르면 해당 기능을 담당하는 파일로 대응시킨다.

| 담당 | 예상 파일 또는 영역 | 주요 업무 |
|---|---|---|
| 주은·은빈 | `robot_pose_node.py` | Pumpkin / Boo 지도 위치 제공 |
| 주은·은빈 | `pumpkin_controller_node.py` | Pumpkin 키보드 제어 연동 |
| 주은·은빈 | `boo_fsm.py` | Boo 행동 상태 전환 |
| 주은·은빈 | `boo_controller_node.py` | Boo 이동 및 Nav2 연동 |
| 주은·은빈 | `game_manager_node.py` | 게임 상태 관리 및 최종 판정 |
| 주은·은빈 | `rules.py` | 사탕, 잡힘, 성공·실패 규칙 |
| 주은·은빈 | `safety_supervisor_node.py` | 안전 상태 판단 |
| 주은·은빈 | `velocity_gate_node.py` | 실제 이동 명령 허용 및 차단 |
| 주은·은빈 | ROS–Web Bridge | ROS 인터페이스와 웹 데이터 형식 연결 |
| 승현·원호 | `boo_detector_node.py` | Boo 카메라의 Pumpkin 감지 |
| 승현·원호 | `target_localizer_node.py` | 감지 결과와 로봇 위치 연결, 지도 좌표 및 거리 계산 |
| 성은·민서 | 웹 게임플레이 화면 | 로봇 위치와 게임 상태 시각화 |
| 성은·민서 | 웹 이벤트/UI | 하트, 사탕, Boo 상태, 결과 및 화면 효과 표시 |

### 책임 구분

**게임 관리 담당**

게임 상태의 최종 결정권을 가진다. 웹이나 인식 노드가 직접 사탕 획득, 잡힘, 게임 성공 여부를 확정하지 않는다.

**인식 및 위치 계산 담당**

카메라 감지와 위치 추정 결과를 전달한다. 실제 추격 행동이나 게임 종료 여부를 결정하지 않는다.

**로봇 제어 담당**

Boo FSM, Nav2, Pumpkin 키보드 제어를 구현한다. 필요한 관측 및 게임 상태를 구독하여 행동을 결정한다.

**웹 담당**

ROS에서 받은 데이터를 웹 화면 형식으로 변환한다. 표시를 위한 좌표 변환은 허용하지만 게임의 핵심 규칙을 웹에서 중복 판정하지 않는다.

## 4. 전체 ROS 2 인터페이스 목록

ROS 2 메시지 타입은 `패키지/msg/메시지명`, 서비스 타입은 `패키지/srv/서비스명`으로 표기한다.

### 4.1 Topic 및 Service 계약

| 이름 | 자료형 | 발행자 / 서비스 서버 | 주요 구독자 / 클라이언트 |
|---|---|---|---|
| `/tob/pumpkin/pose` | `geometry_msgs/msg/PoseStamped` | Pumpkin 위치 노드 | 게임 관리자, 대상 위치 계산, 웹 연결부 |
| `/tob/boo/pose` | `geometry_msgs/msg/PoseStamped` | Boo 위치 노드 | 게임 관리자, 대상 위치 계산, 웹 연결부 |
| `/tob/perception/pumpkin_detection` | `tob_interfaces/msg/TargetObservation` | Pumpkin 감지 노드 | 대상 위치 계산 노드 |
| `/tob/target/observation` | `tob_interfaces/msg/TargetObservation` | 대상 위치 계산 노드 | Boo FSM, 필요한 게임 판정 노드 |
| `/tob/game/state` | `tob_interfaces/msg/GameState` | 게임 관리 노드 | 웹 연결부, 제어 연동 노드 |
| `/tob/game/event` | `tob_interfaces/msg/GameEvent` | 게임 관리 노드 | 웹 연결부, 게임 기록 기능 |
| `/tob/boo/state` | `tob_interfaces/msg/BooState` | Boo FSM | 웹 연결부, 게임 관리 노드 |
| `/tob/pumpkin/safety` | `tob_interfaces/msg/SafetyState` | 안전 감독 노드 | Pumpkin 이동 명령 게이트 |
| `/tob/boo/safety` | `tob_interfaces/msg/SafetyState` | 안전 감독 노드 | Boo 이동 명령 게이트 |
| `/tob/game/command` | `tob_interfaces/srv/GameCommand` | 게임 관리 노드 | 웹 ROS 연결부 |
| `/tob/pumpkin/cmd_request` | `geometry_msgs/msg/TwistStamped` | 웹 ROS 연결부 (키보드 조작) | `pumpkin_controller_node.py` |
| `/tob/pumpkin/cmd_manual` | `geometry_msgs/msg/TwistStamped` | `pumpkin_controller_node.py` | Pumpkin 이동 명령 게이트 |
| `/tob/pumpkin/cmd_auto` | `geometry_msgs/msg/TwistStamped` | Pumpkin Nav2 (예정) | Pumpkin 이동 명령 게이트 |
| `/tob/pumpkin/control_mode` | `std_msgs/msg/String` (`manual`·`auto`·`stop`, TRANSIENT_LOCAL) | 미정 (Nav2 연동 시 결정) | Pumpkin 이동 명령 게이트 |

Pumpkin 이동 명령 경로: `웹 → /tob/pumpkin/cmd_request → pumpkin_controller(게임 RUNNING 확인) → /tob/pumpkin/cmd_manual → velocity_gate(모드·만료·안전·속도 상한) → 로봇 cmd_vel`. pumpkin_controller는 `game_manager`의 `/tob/game/state`가 RUNNING이고 만료되지 않았을 때만 요청을 넘긴다. 로봇 cmd_vel 토픽과 메시지 형식은 현재 `tob_safety/config/safety.yaml`의 `output_*` 파라미터에서 정한다.

### 4.2 로봇 이름과 실제 토픽 연결

논리적 로봇 이름은 다음과 같이 통일한다.

- 플레이어 로봇: `pumpkin`
- 추격 로봇: `boo`
- 카메라 감지 출처: `boo_camera`

실제 TurtleBot4의 번호, 네임스페이스, 카메라 영상 토픽, TF 및 속도 명령 토픽은 실행 설정에서 매핑한다.

게임 로직에서 `/robot1`, `/robot2`와 같은 실제 로봇 번호를 직접 가정하지 않는다.

맵상의 위치를 나타내는 논리 토픽은 `/tob/...`을 기준으로 통일한다.

## 5. 커스텀 인터페이스별 상세 정의

### 5.1 GameState.msg — 전체 게임 상태

**역할**

현재 회차의 게임 진행 상태를 한 번에 전달하는 스냅샷 메시지이다.

웹 또는 다른 ROS 노드가 이 메시지 하나만으로 현재 게임 상태를 이해할 수 있도록 한다.

**발행**

- 담당: 주은·은빈
- 노드: `game_manager_node.py`
- 토픽: `/tob/game/state`

**사용**

- 웹 연결부: 현재 게임 상태를 웹에 전달
- 성은·민서: 화면에 레벨, 시간, 하트, 사탕 및 결과 표시
- 제어 연동 노드: 진행, 일시정지, 종료 상태 확인

**포함할 정보**

- 회차 식별자 `round_id`
- 현재 레벨
- 게임 진행 상태
- 경과 시간 및 남은 시간
- 현재 하트 및 최대 하트
- 획득한 사탕 목록과 전체 사탕 수
- 탈출 가능 여부 `exit_enabled`
- 게임 종료 또는 상태 변경 사유

**사용 규칙**

- 게임 관리 노드만 최종 상태를 변경한다.
- 웹은 이 메시지로 게임 화면을 복원한다.
- 일시적인 시각 효과는 GameEvent를 참고한다.
- 새 구독자를 위해 현재 게임 상태를 주기적으로 발행한다.
- 과거 이벤트 전체를 보관할 필요는 없다.
- 메시지를 받지 못해 상태가 만료되면 제어 노드는 이전 RUNNING 상태만 믿고 이동을 계속하지 않는다.

**완료 기준**

- 현재 진행 중인 레벨과 회차를 확인할 수 있다.
- 하트, 사탕, 타이머, 탈출 가능 여부를 표시할 수 있다.
- 게임 성공과 실패를 구분할 수 있다.
- 새로 연결된 웹 클라이언트가 다음 유효한 상태 메시지로 화면을 복원할 수 있다.

### 5.2 GameEvent.msg — 주요 게임 이벤트

**역할**

게임에서 발생한 개별 사건을 전달한다.

GameState가 현재 상태를 나타낸다면, GameEvent는 특정 순간에 발생한 사건을 나타낸다.

**발행**

- 담당: 주은·은빈
- 노드: `game_manager_node.py`
- 토픽: `/tob/game/event`

**사용**

- 웹 연결부: 게임 이벤트 전달
- 성은·민서: 사탕 획득, 피격, 성공·실패 화면 효과
- 기록 기능: 필요한 게임 결과와 통계 저장

**주요 이벤트**

- `CANDY_COLLECTED`: 사탕 획득
- `HIT`: 피격 및 하트 감소
- `CLEARED`: 레벨 성공
- `FAILED`: 레벨 실패

**사용 규칙**

- 이벤트 발생 시점에 발행한다.
- 전체 게임 상태를 이벤트마다 복사하여 전달하지 않는다.
- 같은 사건에 대해 중복 효과가 발생하지 않도록 발행 로직에서 중복을 방지한다.
- 이벤트 순번을 별도로 추가하지 않는다.
- 과거 이벤트 재생 시스템을 만들지 않는다.
- 최종 게임 결과는 `round_id`를 기준으로 중복 저장하지 않는다.
- 이벤트 토픽만으로 게임 상태를 복원하지 않는다. 현재 상태는 GameState가 기준이다.
- 별도의 탈출문 OPEN 이벤트는 사용하지 않는다.

**완료 기준**

- 사탕 획득과 하트 감소 시 각각 올바른 이벤트가 발생한다.
- 레벨 성공과 실패 시 이벤트가 발생한다.
- 웹에서 해당 이벤트에 맞는 화면 효과를 표시할 수 있다.
- 이벤트를 받지 못한 경우에도 현재 GameState는 정상적으로 표시된다.

### 5.3 BooState.msg — Boo 행동 상태

**역할**

Boo가 현재 어떤 행동을 수행하고 있는지 전달한다.

Boo의 행동 결정과 상태 전환은 FSM에서 처리하고, BooState는 결정된 상태를 다른 노드와 웹에 알려주는 데 사용한다.

**발행**

- 담당: 주은·은빈
- 노드: `boo_fsm.py`
- 토픽: `/tob/boo/state`

**사용**

- 웹 연결부: Boo 행동 상태 전달
- 성은·민서: 순찰, 발견, 추격, 탐색 상태 표현
- 게임 관리자: 필요할 경우 Boo의 현재 상태 참고

**주요 상태**

- `IDLE`: 대기
- `PATROL`: 지정 경로 순찰
- `SUSPECT`: 대상 감지 후 의심 상태
- `CHASE`: 유효한 목표 정보를 이용한 추격
- `SEARCH`: 마지막 유효 관측 위치 주변 탐색

**포함할 정보**

- 현재 행동 상태
- Pumpkin 감지 여부
- 의심도
- Nav2 목표 활성화 여부
- 마지막 유효 관측 위치 및 유효 여부
- 현재 행동 상태의 이유

**사용 규칙**

- Boo FSM이 행동 전환을 결정한다.
- 웹은 Boo의 실제 행동을 직접 제어하지 않는다.
- 최신 감지를 잃으면 현재 감지 상태를 거짓으로 변경한다.
- 감지 상실 후 마지막 위치를 기억할 수 있지만, 새로운 관측으로 취급하지 않는다.
- 마지막 관측 위치로 이동하거나 순찰에 복귀하는 결정은 FSM이 내린다.
- Nav2 이동 목표의 생성, 취소 및 변경은 제어 노드에서 수행한다.
- BooState 자체는 속도 명령이나 Nav2 목표를 전달하는 메시지가 아니다.

**완료 기준**

- Boo가 현재 순찰 중인지 추격 중인지 확인할 수 있다.
- 감지 여부와 마지막 유효 관측 위치를 구분할 수 있다.
- 감지 상실 후에도 Boo의 상태가 일관되게 표시된다.
- 실제 Nav2 동작과 BooState가 모순되지 않는다.

### 5.4 TargetObservation.msg — Pumpkin 감지 및 지도 위치

**역할**

카메라가 Pumpkin을 감지한 결과와 해당 관측에 연결된 지도 위치 정보를 전달한다.

동일한 메시지 타입을 감지 단계와 위치 계산 단계에서 사용하지만 두 토픽의 의미는 구분한다.

**1단계: 카메라 감지**

- 담당: 승현·원호
- 노드: `boo_detector_node.py`
- 토픽: `/tob/perception/pumpkin_detection`
- 구독: `target_localizer_node.py`

**2단계: 지도 위치 계산**

- 담당: 승현·원호
- 노드: `target_localizer_node.py`
- 토픽: `/tob/target/observation`
- 구독: `boo_fsm.py`, 필요한 게임 판정 노드

**포함할 정보**

- 관측 시각
- 감지 출처 `boo_camera`
- 대상 감지 여부 `detected`
- 감지 신뢰도 및 바운딩 박스 정보
- 지도 좌표 유효 여부 `map_valid`
- 지도상 목표 위치
- Boo와 Pumpkin 사이의 거리

**감지 노드 규칙**

- 새로운 영상 프레임을 처리할 때마다 감지 결과를 전달한다.
- 대상이 없으면 `detected = false`로 발행한다.
- 감지 단계에서는 지도 위치를 결정하지 않는다.
- 감지 노드가 발행하는 `map_valid`는 항상 `false`이다.
- 영상 촬영 시각을 유지한다.
- 영상 입력 자체가 끊긴 경우 과거 감지 결과에 새 시각만 붙여 재발행하지 않는다.
- 영상이 끊긴 상황과 정상 영상에서 대상이 없는 상황을 구분할 수 있도록 수신자는 데이터 만료시간을 검사한다.

**위치 계산 노드 규칙**

- 감지 결과와 두 로봇의 지도 위치를 사용한다.
- 좌표계 및 시각이 유효한 데이터만 결합한다.
- 감지 시각에 충분히 가까운 위치 정보만 사용한다.
- 오래된 Pumpkin 위치를 새로운 감지 결과와 임의로 결합하지 않는다.
- 좌표의 유한값, 자료 최신성, 허용 시각 차이를 검사한다.
- 유효성 검사를 모두 통과한 경우에만 `map_valid = true`로 설정한다.
- 위치를 계산할 수 없는 경우 `map_valid = false`로 전달한다.
- 무효인 좌표를 `(0, 0)`의 실제 목표 위치로 간주하지 않는다.

**거리 계산**

Level 1은 깊이 카메라 기반 거리 추정을 사용하지 않는다.

Boo와 Pumpkin의 유효한 지도 위치가 있을 때, 두 위치의 평면 유클리드 거리를 계산한다.

`distance_m = sqrt((pumpkin_x - boo_x)^2 + (pumpkin_y - boo_y)^2)`

이 거리는 지도 좌표 기반 추정 거리이며 카메라가 직접 측정한 깊이 값이 아니다.

**중요: 감지 상실 후 위치 정보 접근 제한**

Pumpkin은 계속 이동할 수 있으므로 `/tob/pumpkin/pose`는 갱신될 수 있다.

그러나 Boo가 Pumpkin을 보지 못하는 동안 최신 Pumpkin 위치를 추격 목표로 사용하면 게임의 숨기/도망치기 규칙이 무의미해진다.

따라서 다음을 지킨다.

- Boo FSM은 유효한 TargetObservation을 추격 정보의 기준으로 사용한다.
- 현재 감지가 없으면 Pumpkin의 새 지도 위치를 새로운 추격 관측으로 사용하지 않는다.
- 마지막 유효 관측 위치는 보관할 수 있다.
- 감지 상실 후 다음 행동은 Boo FSM에서 결정한다.
- 게임 관리 노드는 사탕, 탈출존 등 게임 규칙 판정을 위해 Pumpkin의 실제 지도 위치를 사용할 수 있다.
- **게임 판정을 위한 실제 위치와 Boo의 추격을 위한 관측 위치는 사용 목적을 구분한다.**

**완료 기준**

- Pumpkin 감지 여부를 전달할 수 있다.
- 감지 성공과 지도 위치 계산 성공을 별도로 구분할 수 있다.
- 위치 계산 실패 시 Boo가 무효한 좌표를 향해 이동하지 않는다.
- 감지 상실 후 실제 Pumpkin 위치가 Boo의 추격 목표로 계속 갱신되지 않는다.
- Boo FSM이 마지막 유효 관측을 이용하여 적절한 행동을 결정할 수 있다.

### 5.5 SafetyState.msg — 로봇 이동 안전

**역할**

Pumpkin과 Boo의 이동 허용 여부를 전달한다.

이 메시지는 안전 판단 결과를 나타내며, 실제 속도 명령 차단은 이동 명령 게이트에서 수행한다.

**발행**

- 담당: 주은·은빈
- 노드: `safety_supervisor_node.py`
- 토픽:
  - `/tob/pumpkin/safety`
  - `/tob/boo/safety`

**사용**

- `velocity_gate_node.py`: 이동 허용 및 차단
- Pumpkin 제어 노드: 제어 상태 확인
- Boo 제어 노드: 제어 상태 확인
- 게임 관리자: 필요시 안전 정지 상태를 게임 진행에 반영

**포함할 정보**

- 판단 시각
- 대상 로봇 식별자
- 이동 허용 여부 `motion_allowed`
- 판단 사유
- 안전 판단 유효시간 `valid_for_s`

**사용 규칙**

- 두 로봇의 안전 상태를 독립적으로 판단한다.
- 안전 허용 정보는 무기한 유효하지 않다.
- 발행 시각과 실제 수신 중단 시간을 모두 검사한다.
- 안전 상태 메시지가 만료되면 이동을 허용하지 않는다.
- 안전 감시 노드가 중단되어도 과거 이동 허가가 계속 유지되지 않도록 한다.
- 오래된 센서·안전 입력에 새 시각만 부여하여 이동을 허용하지 않는다.
- 안전 판단 결과가 거짓이면 이동 명령을 차단한다.
- 게임 시작 및 재개 명령이 들어와도 안전 조건을 우회하지 않는다.
- 게임 명령은 비상정지를 해제하는 기능을 제공하지 않는다.

**완료 기준**

- Pumpkin과 Boo의 이동 허용 여부를 독립적으로 확인할 수 있다.
- 안전 상태가 거짓일 때 실제 이동 명령을 차단한다.
- 안전 메시지 수신이 중단되었을 때 안전한 정지 상태로 전환한다.
- 안전 상태가 오래되었을 때 이전 허가를 재사용하지 않는다.

### 5.6 GameCommand.srv — 게임 진행 명령

**역할**

웹에서 게임 진행을 요청하고, 게임 관리 노드로부터 명령 처리 결과를 받는다.

게임의 실제 상태 변경은 게임 관리 노드에서 처리한다.

**서비스 서버**

- 담당: 주은·은빈
- 노드: `game_manager_node.py`
- 서비스: `/tob/game/command`

**서비스 클라이언트**

- 웹 ROS 연결부
- 사용자의 시작·일시정지·재개·초기화 요청을 ROS 서비스로 변환

**명령 종류**

- `START`: 새로운 회차 시작
- `PAUSE`: 진행 중인 게임 일시정지
- `RESUME`: 일시정지된 게임 재개
- `RESET`: 게임 상태 초기화

**요청 정보**

- 명령 종류
- 레벨
- 대상 회차 식별자

**응답 정보**

- 명령 수락 여부
- 처리 결과 메시지
- 회차 식별자
- 처리 후 게임 진행 상태

**완료 기준**

- 웹에서 네 가지 게임 명령을 호출할 수 있다.
- 허용하지 않는 상태 전환을 거절할 수 있다.
- 회차 식별자가 다른 요청을 거절할 수 있다.
- 명령 처리 후 GameState에 변경된 상태가 반영된다.
- 서비스 응답과 게임 상태가 서로 모순되지 않는다.

## 6. 좌표계 및 시간 규칙

### 6.1 좌표계

- 두 로봇은 동일한 논리적 지도 좌표계를 사용한다.
- 기본 좌표계 이름은 `map`이다.
- 위치 단위는 미터(m)이다.
- 두 로봇의 지도 원점과 방향이 실제로 일치해야 한다.
- 좌표계 이름이 같더라도 서로 독립적으로 만들어진 지도라면 그대로 비교하지 않는다.
- TF 변환이 필요한 경우 변환 성공 여부와 시각을 검사한다.
- 지도 좌표를 확보할 수 없으면 유효하지 않은 위치를 발행하지 않는다.

### 6.2 데이터 시각

- 로봇 위치의 시각은 실제 위치를 얻은 시각을 유지한다.
- 카메라 관측의 시각은 영상 촬영 시각을 유지한다.
- 수신 시각으로 원본 관측 시각을 임의로 덮어쓰지 않는다.
- 처리 지연 또는 통신 지연이 있더라도 오래된 데이터를 새로운 관측으로 간주하지 않는다.
- 로봇 및 컴퓨터의 시계를 동기화한다.
- 시뮬레이션에서는 관련 노드의 `use_sim_time` 설정과 `/clock` 사용 여부를 통일한다.
- 시뮬레이션 시각과 실제 시스템 시각을 임의로 혼합하지 않는다.

### 6.3 최신성 검사

각 데이터를 사용하는 노드는 해당 자료의 유효기간을 확인한다.

- 위치 유효시간
- 감지 유효시간
- 상태 유효시간
- 안전 허용 유효시간
- 감지와 위치 사이의 허용 시각 차이

구체적인 시간 기준은 YAML에서 관리한다.

수신자는 메시지 원본 시각과 로컬 수신 경과시간을 필요에 따라 함께 검사한다.

위치나 감지가 유효하지 않은 경우 원점으로 대체하거나 마지막 값을 현재 값처럼 갱신하지 않는다.

### 6.4 웹 좌표

웹 화면은 지도 좌표를 화면의 픽셀 좌표로 변환하여 표시한다.

이 변환은 시각화를 위한 것으로, 게임의 공식 위치 판정에 사용하지 않는다.

게임 판정은 ROS의 지도 좌표를 기준으로 한다.

## 7. 감지 → 위치 계산 → Boo 추격 흐름

### 7.1 정상 감지

1. Boo 카메라가 새로운 영상을 제공한다.
2. `boo_detector_node.py`가 Pumpkin을 감지한다.
3. 감지 결과를 `/tob/perception/pumpkin_detection`으로 발행한다.
4. `target_localizer_node.py`가 감지 결과를 수신한다.
5. Pumpkin 및 Boo의 지도 위치와 관측 시각을 검사한다.
6. 검증에 성공하면 목표 지도 위치와 거리를 계산한다.
7. `/tob/target/observation`으로 결과를 발행한다.
8. Boo FSM이 유효한 관측 정보를 사용하여 상태를 전환한다.
9. Boo 제어 노드가 FSM 결정에 따라 Nav2 목표를 설정한다.

### 7.2 감지 실패

새 영상에서 Pumpkin이 보이지 않으면 감지 노드는 `detected = false`로 전달한다.

위치 계산 노드는 새로운 유효 관측 위치를 만들지 않는다.

Boo FSM은 현재 감지 상태와 마지막 유효 관측을 구분한다.

마지막 관측 위치로 탐색하거나 순찰로 복귀하는 행동은 FSM 규칙에 따른다.

### 7.3 카메라 입력 중단

영상 자체가 들어오지 않으면 감지 노드는 과거 프레임의 결과를 새로운 시각으로 반복 발행하지 않는다.

Boo FSM은 관측 유효시간 만료를 통해 새로운 감지 정보가 들어오지 않는 상황을 판단한다.

### 7.4 무효한 지도 위치

`detected = true`여도 `map_valid = false`일 수 있다.

이 경우 카메라에 대상이 보였다는 정보와 지도상 추격 목표가 유효하다는 정보는 다르다.

Boo FSM은 해당 메시지의 무효한 좌표를 새로운 Nav2 목표로 사용하지 않는다.

## 8. 게임 규칙과 상태 관리

### 8.1 최종 판정 책임

게임 관리 노드만 다음 사건을 최종 판정한다.

- 사탕 획득
- 하트 감소
- 잡힘에 따른 실패
- 시간 초과
- 탈출 성공
- 회차 종료

감지 노드는 게임 성공·실패를 결정하지 않는다.

웹은 게임 판정 결과를 표시하며 동일 규칙을 별도로 실행하지 않는다.

### 8.2 사탕 획득

Pumpkin의 유효한 지도 위치와 사탕 위치를 비교한다.

레벨 설정에 정의된 판정 반경 안에 진입하면 사탕을 획득한 것으로 처리한다.

한 번 획득한 사탕은 같은 회차에서 중복 획득하지 않는다.

획득 상태는 GameState에 반영하고 필요한 GameEvent를 발행한다.

### 8.3 탈출 성공

사탕을 전부 획득하면 `exit_enabled = true`가 된다.

탈출 가능 상태에서 Pumpkin이 탈출존 판정 영역에 진입하면 즉시 게임을 성공 처리한다.

탈출존에서 대기하는 시간은 없다.

탈출문 열림 상태, 문 열림 완료 이벤트, 별도 대기 타이머는 사용하지 않는다.

탈출 가능 상태가 아니면 탈출존에 진입해도 레벨 성공으로 처리하지 않는다.

### 8.4 Boo에게 잡힘

잡힘 판정은 Level 1 설정을 기준으로 게임 관리 노드에서 수행한다.

필요한 판정 조건은 다음과 같다.

- 두 로봇 사이의 거리
- Pumpkin에 대한 유효한 감지 여부
- 조건의 지속시간
- 하트 및 연속 피격 제한

단순히 두 로봇의 거리만 가까워졌다고 즉시 잡힌 것으로 처리할지는 레벨 규칙에서 명시적으로 결정한다.

감지가 유효하지 않은 경우 잡힘 지속시간을 어떻게 처리할지도 동일한 규칙을 따른다.

### 8.5 게임 실패

설정된 실패 조건을 충족하면 게임을 실패 처리한다.

예를 들어 제한시간 초과나 하트 소진 여부는 `level1.yaml`의 규칙을 사용한다.

실패 판정 후 결과를 GameState에 반영하고 GameEvent를 발행한다.

### 8.6 중복 판정 방지

- 한 사탕은 회차 내에서 한 번만 획득한다.
- 한 회차는 하나의 최종 종료 결과를 가진다.
- 종료 이후 새로운 게임 이벤트가 중복 적용되지 않도록 한다.
- 게임 결과 저장은 회차 식별자를 기준으로 중복을 방지한다.
- 성공과 실패가 동시에 성립하는 경우 우선순위는 별도 설정 또는 규칙에서 명확히 결정한다.

## 9. 게임 명령 및 상태 전환

### 9.1 게임 상태

- `READY`: 시작 준비
- `RUNNING`: 게임 진행
- `PAUSED`: 일시정지
- `CLEARED`: 레벨 성공
- `FAILED`: 레벨 실패

실제 상태 상수값은 `GameState.msg` 정의를 따른다.

### 9.2 START

- READY, CLEARED, FAILED 상태에서 요청할 수 있다.
- 지정한 레벨이 지원되는지 확인한다.
- 게임 시작 전 필수 준비 조건을 확인한다.
- 준비 조건을 통과하면 새로운 `round_id`를 생성한다.
- 게임 타이머와 회차 데이터를 초기화한다.
- 게임 상태를 RUNNING으로 변경한다.
- 새로운 GameState를 발행한다.

준비 조건은 최소한 필요한 위치 정보, 설정 파일, 제어 및 안전 상태를 포함하도록 정의한다.

### 9.3 PAUSE

- RUNNING 상태에서만 요청할 수 있다.
- 요청의 `round_id`가 현재 회차와 일치해야 한다.
- 게임 상태를 PAUSED로 변경한다.
- 게임 진행시간과 잡힘 누적시간을 정지한다.
- 이동 목표를 취소하고 로봇 정지를 요청한다.
- 기존 이동 명령이 계속 적용되지 않도록 제어 계층에서 차단한다.

### 9.4 RESUME

- PAUSED 상태에서만 요청할 수 있다.
- 요청의 `round_id`가 현재 회차와 일치해야 한다.
- 필요한 안전 및 준비 조건을 다시 확인한다.
- 게임 상태를 RUNNING으로 변경한다.
- 게임 타이머를 재개한다.
- 일시정지 이전의 오래된 키보드 입력이나 속도 명령을 재실행하지 않는다.
- Boo의 다음 이동 목표는 현재 FSM 상태와 유효한 데이터에 따라 다시 결정한다.

### 9.5 RESET

- 현재 게임 회차를 초기화한다.
- 활성 회차가 있다면 해당 회차의 식별자가 일치해야 한다.
- 게임 상태를 READY로 변경한다.
- 회차 식별자를 비운다.
- 사탕, 하트, 타이머 등 회차 데이터를 초기화한다.
- 기존 Nav2 목표를 취소하고 로봇 정지를 요청한다.

### 9.6 잘못된 요청

다음 요청은 거절한다.

- 지원하지 않는 명령
- 지원하지 않는 레벨
- 현재 상태에서 허용하지 않는 명령
- 현재 회차와 일치하지 않는 회차 식별자
- 필수 시작 조건을 충족하지 못한 요청

서비스는 수락 여부와 거절 사유를 응답한다.

### 9.7 명령 응답과 실제 로봇 정지

`GameCommand`의 `accepted = true`는 게임 관리 노드가 명령을 수락했다는 뜻이다.

이는 실제 로봇이 이미 완전히 정지했음을 보장하지 않는다.

Nav2 목표 취소와 속도 명령 차단은 별도 제어 계층에서 처리하고 검증한다.

특히 PAUSE, RESET, 게임 종료 시에는 오래된 이동 명령이 다시 실행되지 않도록 한다.

게임 명령으로 안전 차단이나 비상정지를 임의로 해제하지 않는다.

## 10. 통신 및 QoS 정책

### 10.1 프로젝트 상태 메시지

다음 메시지는 초기 권장 설정으로 통일한다.

- GameState
- BooState
- TargetObservation
- SafetyState
- 두 로봇 위치 토픽

**권장 QoS**

- Reliability: `RELIABLE`
- Durability: `VOLATILE`
- History: `KEEP_LAST`
- Depth: `1`

이는 최신 상태를 사용하는 인터페이스의 초기 권장 설정이다. 실제 통신 상대와 QoS 호환성을 확인해야 한다.

`RELIABLE`은 통신 중 정상적인 전달을 지원하지만, 연결이 끊긴 동안 발생한 모든 메시지나 늦게 참가한 구독자에게 과거 데이터를 자동으로 제공한다는 뜻은 아니다.

### 10.2 이벤트 메시지

GameEvent는 다음 구성을 권장한다.

- Reliability: `RELIABLE`
- Durability: `VOLATILE`
- History: `KEEP_LAST`
- Depth: `10`

Depth 10은 메시지 이력을 영구 저장한다는 뜻이 아니라 통신 계층의 최근 샘플 보관 깊이를 의미한다.

새로 접속한 웹 클라이언트는 GameState를 통해 현재 게임 상태를 확인한다.

### 10.3 실제 카메라 토픽

카메라의 원본 이미지 구독 QoS는 카메라 드라이버가 사용하는 설정과 호환되도록 한다.

카메라가 사용하는 QoS를 확인하지 않고 프로젝트 기본 QoS를 무조건 적용하지 않는다.

### 10.4 발행 방식

**주기 발행**

- Pumpkin 위치
- Boo 위치
- GameState
- BooState
- SafetyState

주기 발행은 현재 유효한 데이터가 있다는 전제에서 수행한다.

새로운 위치 측정이 없을 때 과거 위치의 시각을 현재 시각으로 변경하여 발행하지 않는다.

**새 영상 기준 발행**

- Pumpkin Detection
- TargetObservation

감지와 관측은 처리한 새 영상에 맞춰 발행한다.

영상 입력이 중단된 경우 과거 결과를 새로운 영상처럼 재발행하지 않는다.

**사건 발생 시 발행**

- GameEvent

게임 이벤트는 실제 사건이 발생했을 때 발행한다.

### 10.5 통신 중단

- 로봇 위치 정보가 만료되면 해당 위치를 사용하는 판정을 수행하지 않는다.
- 목표 관측이 만료되면 Boo가 새로운 유효 관측으로 취급하지 않는다.
- 게임 상태가 만료되면 제어 노드는 이전 실행 허가를 계속 사용하지 않는다.
- 안전 허용 정보가 만료되면 이동 명령을 차단한다.
- 속도 명령이 만료되면 이전 속도 명령을 유지하지 않는다.

실제 정지 동작은 안전 감독 및 이동 명령 게이트가 담당한다.

## 11. 웹 연결 규칙

### 11.1 ROS와 웹의 역할 구분

**ROS**

- 로봇 위치 계산 및 제어
- 감지와 대상 위치 계산

- ROS 서비스 호출
- 기존 웹 데이터 형식으로 변환
- 웹 클라이언트에 상태 전달
- 게임 결과 저장

**웹 프론트엔드**

- 두 로봇 위치 표시
- 맵 및 게임 상태 시각화
- 키보드 조작 UI와 입력 전달
- 사탕 및 하트 표시
- 타이머 표시
- Boo 행동 효과
- 성공·실패 화면

### 11.2 웹으로 전달할 상태

- 현재 레벨과 회차
- 진행 상태
- 남은 시간과 진행시간
- 현재 하트
- 사탕 획득 상태
- 탈출 가능 여부
- 두 로봇의 지도 위치
- Boo 행동 상태
- 주요 게임 이벤트
- 최종 게임 결과

### 11.3 데이터 변환

웹 연결부는 기존 웹 인터페이스 형식과 ROS 인터페이스 사이의 데이터 구조를 변환한다.

웹과 ROS의 필드명이 다르다면 연결부에서 매핑한다.

게임 규칙을 웹에서 중복 구현하지 않는다.

예를 들어 화면에 사탕 획득 애니메이션을 표시할 수는 있지만, 웹이 단독으로 사탕 획득을 확정하지 않는다.

### 11.4 시간 표시

브라우저는 GameState에서 제공하는 남은 시간과 경과 시간을 기준으로 표시한다.

웹 자체 타이머를 공식 게임 판정 시간으로 사용하지 않는다.

필요한 경우 화면을 부드럽게 보여주기 위한 보간은 허용하지만 다음 GameState를 수신하면 공식 값으로 동기화한다.

## 14. 담당자별 인터페이스 완료 기준

### 주은·은빈 — ROS 게임·제어·안전·웹 연결

- 두 로봇의 위치 토픽이 정상 발행된다.
- GameCommand를 통해 게임 시작, 정지, 재개, 초기화가 가능하다.
- GameState에 공식 게임 상태가 반영된다.
- 사탕 획득과 잡힘 판정이 중복 없이 작동한다.
- 탈출 가능 상태에서 탈출존에 도착하면 즉시 성공한다.
- Boo FSM이 유효한 관측만 추격 정보로 사용한다.
- Nav2 이동 목표가 적절히 생성 및 취소된다.
- 안전 상태가 만료되거나 이동이 허용되지 않으면 실제 이동이 차단된다.
- 웹 연결부가 공식 ROS 상태와 이벤트를 전달한다.

### 승현·원호 — 감지 및 위치 계산

- Boo 카메라에서 Pumpkin 감지가 가능하다.
- 감지 노드가 새 영상마다 결과를 발행한다.
- 감지하지 못한 경우 `detected = false`로 표시한다.
- 감지 노드에서 `map_valid = false`를 유지한다.
- 위치 계산 노드가 유효한 두 로봇 위치를 사용하여 지도 좌표와 거리를 계산한다.
- 위치와 시각이 유효하지 않으면 `map_valid = false`로 처리한다.
- 감지를 잃은 뒤 Pumpkin의 새로운 실제 위치를 추격 관측으로 계속 전달하지 않는다.
- Boo FSM에서 사용할 수 있는 TargetObservation을 제공한다.

### 성은·민서 — 웹 게임 화면

- 두 로봇의 현재 위치가 지도에 표시된다.
- GameState에서 현재 게임 진행 정보를 표시한다.
- 사탕, 하트, 남은 시간과 탈출 가능 여부를 표현한다.
- BooState를 이용해 Boo의 행동 상태를 표시한다.
- GameEvent에 따라 사탕 획득, 피격 및 게임 결과 효과를 표시한다.
- 새로 접속한 경우 GameState를 통해 현재 화면을 복원한다.
- 웹에서 사탕 획득 및 최종 게임 결과를 별도로 판정하지 않는다.
- 표시 좌표 변환은 게임 판정용 원본 지도 좌표를 변경하지 않는다.

## 15. 통합 테스트 체크리스트

### 인터페이스 연결

- [ ] 모든 커스텀 `.msg`와 `.srv`가 정상 빌드된다.
- [ ] 실제 발행 토픽 이름과 자료형이 문서와 일치한다.
- [ ] 발행자와 구독자의 QoS 설정이 호환된다.
- [ ] 두 로봇의 지도 좌표가 동일한 기준으로 정렬된다.
- [ ] 웹 연결부가 ROS 데이터를 정상 수신한다.

### 인식 및 추격

- [ ] Pumpkin 감지 시 TargetObservation이 전달된다.
- [ ] 감지 실패 시 `detected = false`가 전달된다.
- [ ] 위치 계산 실패 시 `map_valid = false`가 된다.
- [ ] Boo가 무효한 위치를 새 추격 목표로 사용하지 않는다.
- [ ] Pumpkin이 숨어 있는 동안 실제 위치가 Boo의 새 추격 목표로 갱신되지 않는다.
- [ ] 카메라 연결 중단 시 오래된 감지가 만료된다.

### 게임 규칙

- [ ] 사탕을 획득하면 GameState와 GameEvent가 갱신된다.
- [ ] 같은 사탕을 중복 획득하지 않는다.
- [ ] 사탕을 모두 획득하면 `exit_enabled = true`가 된다.
- [ ] 탈출 가능 상태에서 탈출존 진입 시 즉시 성공한다.
- [ ] 탈출 불가능 상태에서 탈출존 진입 시 성공하지 않는다.
- [ ] 성공·실패 이후 최종 결과가 중복 처리되지 않는다.

### 명령 및 안전

- [ ] START, PAUSE, RESUME, RESET이 정상 처리된다.
- [ ] 유효하지 않은 상태 전환 요청이 거절된다.
- [ ] 잘못된 회차 식별자로 명령을 실행할 수 없다.
- [ ] PAUSE 시 타이머와 잡힘 누적시간이 정지한다.
- [ ] PAUSE, RESET, 게임 종료 시 이동 명령이 안전하게 차단된다.
- [ ] RESUME 시 오래된 속도 명령이 재실행되지 않는다.
- [ ] 안전 상태가 만료되면 이동이 차단된다.
- [ ] 게임 명령으로 비상정지를 해제하지 못한다.

### 웹 화면

- [ ] 두 로봇의 지도 위치가 올바르게 표시된다.
- [ ] 사탕과 하트가 GameState에 맞게 표시된다.
- [ ] Boo 행동 상태가 올바르게 표시된다.
- [ ] 성공과 실패 시 화면이 올바르게 변경된다.
- [ ] 웹을 새로 연결해도 현재 게임 상태가 복원된다.

## 16. 최종 설계 원칙

**1. GameManager는 게임의 유일한 최종 판정자다.**

게임 상태와 규칙을 웹이나 다른 노드에서 중복 판정하지 않는다.

**2. Perception은 관측을 제공하고 Control은 행동을 결정한다.**

감지와 추격 로직을 한 노드에 혼합하지 않는다.

**3. 위치가 있다는 것과 Boo가 Pumpkin을 발견했다는 것은 다르다.**

실제 지도 위치를 알고 있어도 유효한 카메라 관측이 없다면 새로운 추격 정보로 사용하지 않는다.

**4. 메시지 최신성은 기능 및 안전 조건의 일부다.**

오래된 위치, 감지, 게임 상태, 안전 허용 정보를 현재 데이터처럼 사용하지 않는다.

**5. 웹은 ROS의 공식 게임 상태를 표현한다.**

웹에 별도 게임 판정 시스템을 만들지 않는다.

**6. Level 1은 필요한 기능만 구현한다.**

기존 6개 인터페이스를 중심으로 개발하며, 웹캠·깊이 기반 위치 추정·자동 복귀·복잡한 이벤트 재생 시스템은 추가하지 않는다.

**7. 탈출 조건은 단순하고 명확하게 유지한다.**

사탕을 모두 획득하고 탈출존에 들어오면 즉시 레벨 성공이다.
